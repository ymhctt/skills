# MES 增强版服务总结报告技能

## 功能说明

基于 MES 系统数据生成**增强版专业服务总结报告**，相比标准模式A报告，新增以下核心能力：

| 增强项 | 说明 |
|--------|------|
| **量化交付成果卡片** | 10大交付维度，图标+数字+说明的卡片式展示 |
| **AI综合分析与改进建议** | 项目管理/人员工作/能力提升/客户沟通四维度深度分析 |
| **综合评分矩阵** | 每维度10分制打分 + 综合评分 + 改进方向 |
| **技能覆盖雷达图** | 团队成员技能覆盖度可视化 |
| **工作负荷热力图** | 单日报工时长分布（≤8h / 9-10h / >10h） |
| **交付价值总结** | 6大价值维度的结构化展示 |
| **蓝色科技风格** | 区别于标准模板的暖色风格，采用蓝色渐变科技风 |

## 报告结构（8大章节）

### 第1章：服务报告概述
- 项目基本信息（客户、服务周期、覆盖范围）
- 关键数字总览（报工记录数、总工时、数据库类型数等）

### 第2章：量化交付成果一览
- **10大交付维度卡片**（每个维度包含：图标、数字、标题、说明）：

| 序号 | 交付维度 | 图标 | 计算方式 | 说明模板 |
|------|----------|------|----------|----------|
| 1 | 日常巡检覆盖 | 🔍 | 巡检报工去重日期数 | 覆盖X个巡检日期，Y条巡检报工记录 |
| 2 | 纳管数据库总数 | 🗄️ | 从remark中提取数据库类型去重 | Oracle / AntDB / 磐维DB / ... |
| 3 | 故障处理 | 🔧 | 故障类报工条数 | 处理告警、异常、报错等X次 |
| 4 | 部署交付 | 🚀 | 部署类报工条数 | 安装部署、初始化环境等X次操作 |
| 5 | 迁移升级 | 📦 | 迁移类报工条数 | 数据迁移、版本升级等X次作业 |
| 6 | 安全加固 | 🔒 | 安全类报工条数 | 白名单整改、基线整改等X项 |
| 7 | 备份恢复 | 💾 | 备份类报工条数 | Barman备份、逻辑备份等X次 |
| 8 | 性能优化 | ⚡ | 优化类报工条数 | 慢SQL调优、参数优化等X次 |
| 9 | 专家服务 | 🎯 | 专家/深度分析类报工条数 | 深度分析、专项优化X次 |
| 10 | 产出文档 | 📝 | 文档类报工条数 | 巡检报告、方案文档等X份 |

### 第3章：合同执行情况
- 合同基本信息表
- 合同子项执行卡片（计划工时/已用工时/完成率/进度条）

### 第4章：服务分类分析
- **4个Chart.js图表**：
  1. 服务类型占比（饼图）
  2. 服务人天消耗（水平柱状图）
  3. 月度工时分布（柱状图）
  4. 人员工时分布（水平柱状图）
- 服务类型明细表

### 第5章：交付团队与工时分布
- 人员工时明细表（姓名/团队/工单数/总工时/占比/主要职责）

### 第6章：服务清单明细
- 代表性服务请求抽样表（序号/时间/内容/人员/工时）
- 标注抽样比例（如"15/305条"）

### 第7章：AI综合分析与改进建议

#### 7.0 分析图表
- **技能覆盖雷达图**：每个成员在8大技能维度（巡检/故障/优化/安全/迁移/部署/备份/文档）的覆盖情况
- **工作负荷热力图**：≤8h / 9-10h / >10h 三档分布

#### 7.1 项目管理建议
分析维度：
- 工时分布是否均衡（最高与最低比值）
- 巡检占比是否过高（>40%建议自动化）
- 工时消耗与项目周期是否匹配
- 异构管理能力评估

标记规则：
- 🔴 严重问题：工时偏差>2倍 / 巡检占比>50%
- 🟡 需关注：工时偏差1.5-2倍 / 巡检占比40-50%
- 🟢 表现良好：工时均衡 / 巡检占比<40%

#### 7.2 人员工作建议
分析维度：
- 单日超负荷报工（>8h / >10h / >12h 档位统计）
- 报工备注质量（模糊描述占比）
- 技能覆盖度（全栈/专精/初级）
- 梯队培养建议（工时最少但覆盖维度多的成员）

#### 7.3 能力提升建议
分析维度：
- 性能优化深度（是否仅参数调整，缺少AWR/SQL Plan Baseline等）
- 国产数据库专项能力（报工频次 vs 深度）
- 备份恢复场景覆盖度
- 文档产出价值（标准化文档 vs 知识沉淀）

#### 7.4 客户沟通建议
分析维度：
- 服务请求数量与类型（仅有低优先级说明沟通不足）
- 合规工作可见度（安全整改客户感知度低但价值高）
- 迁移升级风险沟通（高频迁移需审批SOP）
- 定期回顾机制建立

#### 7.5 综合评分矩阵
10分制评分表：

| 维度 | 评分标准 |
|------|----------|
| 📋 项目管理 | 工时均衡度、自动化程度、与周期匹配度、能力沉淀 |
| 👥 人员工作 | 超负荷频次、报工质量、技能覆盖、梯队健康度 |
| 📈 能力提升 | 优化深度、国产库能力、备份覆盖、知识沉淀 |
| 💬 客户沟通 | 服务请求活跃度、合规可见度、风险对齐、回顾机制 |

评分规则：
- **9-10分**：优秀，无明显短板
- **7-8分**：良好，有改进空间
- **5-6分**：一般，存在明显问题
- **3-4分**：较差，需立即改进
- **1-2分**：严重不足

### 第8章：服务结论 - 交付价值总结
- **6大价值维度卡片**：
  1. 🛡️ 多库全面纳管
  2. 📊 巡检体系完善
  3. 🔧 高效故障响应
  4. 📦 大规模迁移升级
  5. 🔒 安全合规保障
  6. 👥 专业驻场团队
- 总结性评价段落

## 数据分析规则

### 报工分类关键词映射

从每条报工的 `remark` 字段提取关键词，按以下规则分类：

| 分类 | 关键词 | 图标 |
|------|--------|------|
| 巡检服务 | 巡检、检查、监控、日常4次、巡检报告 | 🔍 |
| 故障处理 | 故障、告警、异常、报错、ORA-、会话中断、超时、处理 | 🔧 |
| 迁移升级 | 迁移、升级、割接、切换、同步、导入、导出、MTK | 📦 |
| 性能优化 | 优化、调优、慢SQL、参数调整、执行计划、TPS、QPS、DB Time | ⚡ |
| 部署交付 | 安装、部署、初始化、创建集群、环境搭建 | 🚀 |
| 安全加固 | 白名单、基线、口令、安全、等保、整改、重置 | 🔒 |
| 备份恢复 | 备份、恢复、Barman、RMAN、逻辑备份、物理备份 | 💾 |
| 专家服务 | 深度分析、专项优化、根因分析、SPA | 🎯 |
| 产出文档 | 报告、方案、清单、PPT、文档、梳理 | 📝 |

**分类规则**：
- 一条报工可归入多个分类（一条remark可能同时包含"巡检"和"故障"）
- 优先级：故障 > 迁移 > 优化 > 安全 > 部署 > 备份 > 巡检 > 文档 > 专家
- 如果remark无明显关键词，归入"其他"并标注

### 人员主要职责提取

从每人的报工remark中提取高频关键词，形成主要职责描述：
1. 统计每人各分类的报工数量
2. 取前2-3个高频分类
3. 从具体remark中提取最具代表性的工作内容
4. 格式：`{核心工作1}、{核心工作2}、{核心工作3}`

### 技能覆盖度计算

对每个团队成员，按8大技能维度检查是否有相关报工：

```
skill_coverage = {
  "巡检": remark包含"巡检|检查|监控",
  "故障": remark包含"故障|告警|异常|报错|ORA",
  "优化": remark包含"优化|调优|慢SQL|执行计划",
  "安全": remark包含"白名单|基线|口令|安全|等保",
  "迁移": remark包含"迁移|升级|割接|切换|同步",
  "部署": remark包含"安装|部署|初始化|创建",
  "备份": remark包含"备份|恢复|Barman|RMAN",
  "文档": remark包含"报告|方案|清单|PPT|文档"
}
```

每个维度有相关报工 = 1，无 = 0

### 工作负荷分布统计

统计每条报工的 `taskTime` 字段：
- **≤8h**：正常工作日
- **9-10h**：轻度超负荷
- **>10h**：严重超负荷

### 综合评分计算

```
project_mgmt_score = f(工时均衡度, 巡检自动化程度, 工时-周期匹配度)
personnel_score = f(超负荷比例, 报工质量, 技能覆盖度, 梯队健康度)
capability_score = f(优化深度, 国产库能力, 备份覆盖, 知识沉淀)
communication_score = f(服务请求活跃度, 合规可见度, 风险对齐, 回顾机制)

overall_score = weighted_avg(project_mgmt, personnel, capability, communication)
权重: project_mgmt=0.25, personnel=0.25, capability=0.25, communication=0.25
```

## 执行流程

### Step 1: 确认项目与时间范围

向用户确认：
1. 目标项目名称/客户名
2. 报告时间范围（默认当月或项目启动至今）
3. 是否需要特定风格偏好（默认蓝色科技风）

### Step 2: 数据采集

复用 `mes_project_skill` 的数据查询流程：

```bash
# 1. 获取合同信息
mes -o json contract list | grep -i {关键词}

# 2. 获取服务请求
mes -o json service request list --company-id {公司ID} --start-time "{起始} 00:00:00" --end-time "{结束} 23:59:59" --page-size 200

# 3. 获取合同子项
mes -o json contract list-items --contract-id {合同ID} --page-size 50

# 4. 按子项查询报工（确保数据精确）
mes -o json statistics list --acc-id {子项ID} --from {起始日期} --to {结束日期} --page-size 1000

# 5. 合并去重
```

**重要**：必须按 `--acc-id` 查询报工，不能用 `--company-id`，避免混入其他项目数据。

### Step 3: 数据分析

按本技能定义的规则进行：
1. **报工分类**：按关键词映射将每条报工归入9大分类
2. **人员统计**：每人总工时、工单数、主要职责、技能覆盖
3. **负荷分析**：单日报工时长分布
4. **合同执行**：计划工时 vs 已用工时，完成率计算
5. **月度分布**：按月统计工时

### Step 4: AI分析与评分

1. **项目管理评分**（权重25%）：
   - 工时均衡度：最高/最低比 < 1.5 得满分，> 3 扣3分
   - 巡检占比：< 30% 满分，> 50% 扣2分
   - 周期匹配：工时完成率与时间进度偏差 < 5% 满分

2. **人员工作评分**（权重25%）：
   - 超负荷比例：>10h占比 < 5% 满分，> 20% 扣3分
   - 报工质量：模糊描述占比 < 10% 满分，> 30% 扣2分
   - 全栈人数：≥ 3人满分

3. **能力提升评分**（权重25%）：
   - 优化深度：有AWR/执行计划绑定等高阶操作加分
   - 国产库：GoldenDB/AntDB有深度分析（非仅日常操作）加分
   - 备份场景：≥ 3种备份方式满分

4. **客户沟通评分**（权重25%）：
   - 服务请求：> 5个满分，< 2个扣2分
   - 主动汇报：有月报/周报机制加分
   - 风险对齐：迁移有审批SOP加分

### Step 5: 生成HTML报告

1. 按本技能定义的8大章节结构生成
2. 使用蓝色科技风格CSS
3. 嵌入Chart.js图表
4. 写入文件：`/tmp/mes_{项目关键词}_report.html`

### Step 6: 展示与交付

1. 使用 `preview_url` 打开报告
2. 如需推送企业微信，复用 `mes_project_skill` 的消息格式
3. 如需发送邮件，复用 `mes_project_skill` 的邮件配置

## 与 mes_project_skill 的关系

| 对比项 | mes_project_skill | mes_service_report_pro |
|--------|-------------------|------------------------|
| 定位 | 标准项目报告（模式A/B/C） | 增强版服务总结报告 |
| 报告深度 | 基础数据分析 | AI深度分析+评分 |
| 图表类型 | 饼图+柱状图 | +雷达图+热力图 |
| 交付成果 | 表格展示 | 卡片式展示 |
| AI建议 | 无 | 四维度+评分矩阵 |
| 样式风格 | 暖色编辑风(coral/teal) | 蓝色科技风 |
| 触发场景 | 日常汇报 | 验收/高层汇报/深度分析 |

**数据查询复用**：两个技能共享相同的 MES 数据查询流程和校验规则，`mes_service_report_pro` 在数据采集阶段可直接复用 `mes_project_skill` 的 Step 1-2。
