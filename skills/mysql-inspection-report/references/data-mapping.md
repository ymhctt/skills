# 原始采集数据到报告章节的映射

本文件用于帮助从 `mysql_check202604.sh` 的原始输出中，快速定位每个报告章节应使用的数据来源。

## 报告摘要来源
### 1. 实例概览
优先抽取：
- 报告头部项目表（生成时间 / 实例标识 / 目标地址 / MySQL版本）
- `## 系统信息`
- `### 主机与内核`
- `### 网络与磁盘`
- `### 资源与IO`
- `### 全局状态快照`
- `### 连接信息`

### 2. 总体健康评分 / 风险摘要
优先综合以下章节：
- `## 健康检查总结`
- `## 复制状态与建议`
- `## 用户权限审计`
- `## 备份策略检查`
- `## 性能视图分析与异常 SQL`
- `## InnoDB 状态分析与建议`
- `## Error 日志扫描`

## 结构与角色识别来源
### 3. 参数检查与调整建议
优先查看：
- `## 关键配置与建议`
- `### 配置快照`
- `### 建议`
- `### MySQL配置文件(my.cnf)`

### 4. InnoDB 状态分析
优先查看：
- `## InnoDB 状态分析与建议`
- `### Buffer Pool 摘要`
- `### 事务与 Purge`
- `### IO 与刷写`
- `### Redo/Checkpoint`
- `### 行操作统计`

### 5. 锁、事务与死锁分析
优先查看：
- `## InnoDB 状态分析与建议`
- `### 事务与 Purge`
- `SHOW ENGINE INNODB STATUS` 中的事务、锁等待、死锁、semaphore 片段
- 健康总结中与长事务、大事务、锁等待相关的结论

### 6. 错误日志分析
优先查看：
- `## Error 日志扫描`
- `### 最近200行关键异常`
- 健康总结中与 crash、权限错误、复制错误、磁盘/文件系统异常相关的结论

## SQL / 索引 / 结构风险来源
### 7. 慢查询与 TOP SQL 分析
优先查看：
- `## 性能视图分析与异常 SQL`
- `### 全表扫描（sys）`
- `### 临时表与排序（sys）`
- `### 耗时最多（sys）`
- 如有慢日志汇总，优先使用慢日志原始统计

### 8. 连接与线程分析
优先查看：
- `### 全局状态快照`
- `### 连接信息`
- `## 状态多次采样与建议`

关键指标包括：
- `Threads_running`
- `Threads_connected`
- `Max_used_connections`
- `Aborted_clients`
- `Aborted_connects`
- `Connections`
- `Threads_created`
- `Created_tmp_tables`
- `Created_tmp_disk_tables`
- `Table_open_cache_hits`
- `Table_open_cache_misses`
- `Table_open_cache_overflows`

### 9. 表与索引健康检查
优先查看：
- `### 无主键表`
- `### 未使用索引 (Top30)`
- `### 库容量与碎片`
- `#### 碎片 Top10`
- `### 数据库对象统计`

## 复制与拓扑来源
### 10. 复制健康检查
优先查看：
- `## 复制状态与建议`
- `### 异步复制(Receiver) 状态`
- `### 异步复制(Applier) 状态`
- `### SHOW REPLICA STATUS`
- `### Group Replication (MGR) 状态`
- `### Galera/PXC 状态`
- 配置表中的 `read_only` / `super_read_only`

## 资源、安全与可靠性来源
### 11. 资源与容量风险分析
优先查看：
- `### 网络与磁盘`
- `### 资源与IO`
- `### 库容量与碎片`
- `#### 库大小`
- Binlog、慢日志、错误日志相关章节或总结

### 12. 安全与合规配置检查
优先查看：
- `## 用户权限审计`
- `### 账户列表`
- `### root 远程访问检查`
- `## 健康检查总结`
- `## 关键配置与建议` 中与安全、日志、审计相关的参数

### 13. 采集完整性与结论可信度说明
优先查看：
- 报告头部时间信息
- 是否存在 `## Error 日志扫描`
- 是否存在 `## 性能视图分析与异常 SQL`
- 是否存在 `## InnoDB 状态分析与建议`
- 是否存在 `performance_schema` / `sys` 相关输出
- 原始文件中是否仅有单次快照、是否缺失关键章节

### 14. 整改建议清单（按优先级排序）
优先综合：
- `## 健康检查总结`
- `## 关键配置与建议`
- `## 复制状态与建议`
- `## 用户权限审计`
- `## 备份策略检查`
- `## 性能视图分析与异常 SQL`
- `## InnoDB 状态分析与建议`
- `## Error 日志扫描`

## 写作原则
- 如果原始表为空，不要硬写结论；说明“当前未采集到异常项”或“未发现记录”。
- 如果原始建议已经有价值，可以吸收后改写为更面向汇报的语言。
- 如果原始表非常长，只保留最关键的 TopN，并在附录注明“详见原始采集文件”。
- 复制、MGR、Galera/PXC 的判断规则，继续参考 `topology-guidelines.md`，不要重复定义。
