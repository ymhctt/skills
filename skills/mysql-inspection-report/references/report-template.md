# 巡检报告模板

在生成最终 Markdown 报告时，优先遵循以下 14 个核心章节。可根据拓扑删减细节，但不要缺少“实例概览”“总体健康评分 / 风险摘要”“整改建议清单”三个核心部分；不适用章节请明确写“不适用”或“未采集到足够证据”。

# MySQL 巡检深度分析报告

## 1. 实例概览
### 1.1 巡检对象与采集范围
- 实例名称 / 主机信息 / 环境
- 巡检时间
- 采集来源
- 覆盖范围

### 1.2 实例角色与基础信息
- 单节点 / 主备 / MGR / Galera / PXC / 未知多节点
- 节点总数
- 节点角色
- MySQL 版本、运行时间、基础资源概况

### 1.3 运行态概览
- 当前连接数 / 活跃线程数
- QPS / TPS / 读写比例
- 数据量、对象规模、核心负载特征

## 2. 总体健康评分 / 风险摘要
- 对可用性、性能、容量、安全、备份恢复分别给出一句话判断
- 汇总整体健康状态（健康 / 关注 / 风险 / 高风险）
- 问题总数与高/中/低风险数量
- 最需要优先处理的 3~5 项问题

## 3. 参数检查与调整建议
- 关键参数当前值与建议方向
- 参数合理性判断依据
- 调整风险与优先级
- 重点覆盖：Buffer Pool、redo/flush、连接、缓存、临时表、日志、`sql_mode`、`performance_schema`

## 4. InnoDB 状态分析
- Buffer Pool 配置与实际利用率
- 命中率、脏页、flush、pending IO
- Redo / Checkpoint 压力
- Purge、History List Length、行操作统计
- 异常等待或刷写行为

## 5. 锁、事务与死锁分析
- 长事务 / 大事务
- 锁等待 / 死锁
- Metadata Lock 风险
- Undo / Purge 滞后
- 热点更新 / 热点行争用

## 6. 错误日志分析
- 错误类型分类
- 出现次数与时间分布
- 是否存在 crash / 重启 / 复制错误 / 权限错误 / InnoDB 错误
- 当前影响评估与处理建议

## 7. 慢查询与 TOP SQL 分析
- 按总耗时、平均耗时、执行次数输出 Top SQL
- 识别全表扫描、临时表落盘、排序、索引失效等风险
- 区分业务 SQL 与巡检噪声 SQL
- 给出 SQL 优化优先级

## 8. 连接与线程分析
- 连接使用率与峰值
- `Threads_running`、`Threads_connected`、`Max_used_connections`
- Sleep 连接、短连接频繁创建
- `thread_cache_size` 命中情况
- `aborted_connects` / `aborted_clients` 风险

## 9. 表与索引健康检查
- 无主键表
- 重复 / 冗余 / 低效索引
- 未使用索引
- 超大表、碎片、行格式异常
- 字符集 / 排序规则 / 分区使用情况异常

## 10. 复制健康检查
- 主备：复制线程、延迟、GTID、binlog、只读状态
- MGR：成员 ONLINE 状态、PRIMARY 数量、一致性与关键参数
- Galera/PXC：wsrep 状态、flow control、集群连通性
- 单节点：明确说明不适用

## 11. 资源与容量风险分析
- CPU、内存、磁盘、IO 压力
- 数据量与表空间增长趋势
- Binlog、错误日志、慢日志增长风险
- Buffer Pool 与数据量比例
- 中短期扩容或清理建议

## 12. 安全与合规配置检查
- root 远程访问
- 超权账号 / 匿名账号
- `validate_password`、`sql_mode`
- `local_infile`、`secure_file_priv`
- 慢日志 / 错误日志 / 审计能力配置
- SSL / 证书 / 只读限制

## 13. 采集完整性与结论可信度说明
- 已采集数据项与缺失项
- 是否仅有单点快照
- 是否缺失错误日志 / 慢日志 / `performance_schema`
- 哪些结论为高置信度
- 哪些结论需要补采后复核

## 14. 整改建议清单（按优先级排序）
建议使用汇总表：
| 优先级 | 风险级别 | 问题 | 影响范围 | 建议动作 | 证据 |
| --- | --- | --- | --- | --- | --- |

建议按阶段输出：
- 立即处理
- 短期处理
- 持续优化

## 附录 / 原始证据摘录
仅保留关键原始输出片段，例如：
- SHOW REPLICA STATUS 关键字段
- MGR 成员状态
- wsrep 状态
- 健康检查总结表
- 备份 crontab 摘录
- Error Log 关键异常片段

## 写作风格要求
- 摘要先行，细节随后。
- 先给结论，再给证据。
- 每一节优先按“结论 → 关键指标 → 发现的问题 → 影响评估 → 优化建议 → 证据来源”组织。
- 对比类报告必须体现节点差异，不要把每个节点独立写成两份单机报告。
- 对用户已经给出的参考报告风格，优先靠拢其章节组织与表述粒度。
- 大表格与长列表默认只摘录 TopN/最近N，避免正文失控。
