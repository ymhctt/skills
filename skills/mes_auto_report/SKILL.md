# MES 智能报工技能

## 功能说明

将用户自然语言描述的工作内容，自动转换为结构化报工记录并提交 MES 系统。

### 核心能力

1. **自然语言转报工**：用户输入工作内容 → 自动识别工作类型、数据库、量化数据 → 生成结构化 remark → 提交 MES
2. **批量报工**：一次输入多天工作内容 → 自动拆分日期 → 逐条提交
3. **模板化报工**：基于 8 种工作类型模板自动生成符合规范的报工备注
4. **量化数据提取**：自动从工作内容中提取可量化指标（检查X套、耗时X分钟、优化X%等）
5. **合规校验**：自动校验工时上限（10h/日）、remark长度（≥10字）、时间格式等

## 报工模板（五要素）

所有报工必须符合以下结构：

```
【工作类型】+【涉及数据库】+【工作内容】+【工作过程】+【结果状态】+【交付成果】+【明日计划】
```

## 执行流程

### Step 1: 接收用户工作内容

用户输入自然语言描述的工作内容，示例：

```
今天做了以下工作：
1. 巡检了Oracle和GoldenDB，检查了集群状态和等待事件，一切正常
2. 处理了一个GoldenDB的慢SQL问题，加了索引后从10秒降到0.5秒
3. 配合做了数据迁移，导出了20GB数据
```

### Step 2: 信息抽取与结构化

自动识别并提取以下信息：

| 要素 | 提取内容 |
|------|----------|
| 工作日期 | 用户输入日期或默认今天 |
| 工作类型 | 从8类中自动匹配（巡检、故障处理、性能优化等） |
| 涉及数据库 | 提取数据库名称（Oracle、GoldenDB等） |
| 工作内容 | 做了什么 |
| 工作过程 | 怎么做的 |
| 量化数据 | 提取数字指标（检查X套、耗时X分钟、优化X%） |
| 结果状态 | 完成/处理中/已闭环等 |
| 交付成果 | 产出的文档/报告/配置等 |
| 工时 | 用户输入或根据内容估算（需用户确认） |

### Step 3: 生成结构化报工备注

根据工作类型模板，将抽取的信息填充为符合规范的 remark：

```
【巡检】Oracle+GoldenDB 日常巡检，检查集群状态、等待事件，各项指标正常，无异常发现，巡检完成
```

### Step 4: 校验与预览

展示将执行的报工记录，供用户确认：

| 字段 | 值 |
|------|-----|
| 日期 | 2026-05-28 |
| 工时 | 8h |
| 工作类型 | 巡检/故障处理/性能优化 |
| 报工备注 | 【巡检】Oracle+GoldenDB 日常巡检... |
| 关联项目 | 云南移动2026年数据库代维驻场 |

### Step 5: 执行报工

用户确认后执行：

```bash
mes statistics add \
  --type 1 \
  --rid {实施计划ID} \
  --start "{date} 09:00:00" \
  --end "{date} 18:00:00" \
  --hours {hours} \
  --remark "{结构化备注}" \
  --acc-id {合同子项ID} \
  --company-id {公司ID}
```

### Step 6: 结果反馈

报工成功后展示：

```
✅ 报工成功
📅 日期：2026-05-28
⏱️ 工时：8h
📝 备注：【巡检】Oracle+GoldenDB 日常巡检...
🔗 报工ID：12345
```

## 批量报工流程

当用户一次性输入多天时工作内容时：

1. **按日期拆分**：识别"周一"、"5月26日"、"今天"等日期表述
2. **按事项拆分**：识别"1."、"2."、"首先"、"然后"等事项分隔符
3. **逐日生成**：每天生成一条报工记录
4. **逐条确认**：展示所有报工记录，用户确认后批量提交
5. **汇总反馈**：展示批量报工结果汇总

## 缺参处理策略

| 缺失参数 | 处理策略 |
|----------|----------|
| 工作日期 | 默认使用今天，向用户说明 |
| 工时 | 根据工作内容估算，必须用户确认 |
| 涉及数据库 | 追问用户 |
| 量化数据 | 尝试从内容中提取，缺失则标注"待补充" |
| 合同子项 | 使用用户历史报工中最近使用的 acc-id |
| 实施计划 | 使用用户当前活跃的实施计划 |

## 量化数据提取规则

从用户输入中自动提取以下量化指标：

| 指标类型 | 提取规则 | 示例 |
|----------|----------|------|
| 数量 | 提取"X套"、"X个"、"X条"等 | "12套数据库" → 12 |
| 耗时 | 提取"X分钟"、"X小时"、"Xs"等 | "耗时45min" → 45分钟 |
| 百分比 | 提取"X%"、"降至X"等 | "优化92%" → 92% |
| 数据量 | 提取"X GB"、"X TB"等 | "23.7GB数据" → 23.7GB |
| 次数 | 提取"第X次"、"X次"等 | "第2次巡检" → 2 |
| 对比数据 | 提取"从X到Y"、"X→Y"等 | "从12s降至0.3s" |

## 合规校验规则

| 校验项 | 规则 | 处理方式 |
|--------|------|----------|
| 工时上限 | 单日不超过 10h | 超限需标注原因并提醒用户 |
| remark长度 | 最少 10 字 | 自动补充量化数据至达标 |
| 时间格式 | YYYY-MM-DD HH:mm:ss | 自动格式化 |
| 不能跨天 | start 和 end 必须同一天 | 自动拆分为多条报工 |
| 工作类型 | 必须匹配8类之一 | 自动分类或追问用户 |

## 注意事项

1. **禁止模糊描述**：自动将"处理问题"、"配合工作"等模糊描述转换为结构化备注
2. **强制量化**：所有报工必须包含至少1个量化数据
3. **结果导向**：必须包含结果状态（已完成/已闭环/处理中）
4. **成果记录**：必须记录交付成果（报告/文档/配置等）
5. **计划衔接**：建议包含明日计划，保持工作连续性
6. **先预览后提交**：所有报工必须先展示预览，用户确认后再提交
7. **批量提交提示**：批量报工时逐条展示，用户可逐条确认或全部确认
