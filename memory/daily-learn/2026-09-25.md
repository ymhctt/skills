## 📄 并行导出导入RDS.md

使用 `mydumper` 或 `MySQL Shell` 进行全量并行导出，是目前针对远端 RDS 实例最高效的方案。这两个工具都原生支持多线程处理，并能将大表分块（Chunking），极大提升了导出速度。

由于 RDS（如阿里云、AWS、腾讯云等）是托管型数据库，通常会限制 `SUPER` 权限和某些系统库的访问。因此，在导出时**必须避开需要高权限的锁表操作，并过滤掉系统库**。

以下是针对这两个工具量身定制的操作方案：

------

### 方案一：使用 `mydumper` 方案（高度定制化、适合传统文件备份）

`mydumper` 是 C 语言编写的高性能逻辑备份工具，速度极快，生成的是纯 SQL 文本文件（每个表/块一个文件）。

#### 1. 前置准备与安装

- **安装**：在执行导出的服务器上安装（如 CentOS: `yum install mydumper`，Ubuntu: `apt install mydumper`）。
- **网络**：确保该服务器到 RDS 之间带宽充足。

#### 2. 核心导出命令

Bash

```
mydumper -h <RDS连接地址> -P <端口> -u <用户名> -p '<密码>' \
  -o /path/to/backup_dir_$(date +%F) \
  -t 8 \
  -c \
  -r 100000 \
  --trx-consistency-only \
  -G -E -R \
  --regex '^(?!(mysql|sys|information_schema|performance_schema))'
```

#### 3. 关键参数解析（针对 RDS 的特殊优化）

- `-t 8`：开启 8 个并行线程。请根据执行机的 CPU 核心数和 RDS 的剩余性能（CPU/IOPS）进行调整。
- `-r 100000`：**分块提速核心**。将大表按照每 10 万行切分成一个独立文件，让多个线程可以并行导出一个大表，避免单表卡顿。
- `--trx-consistency-only`：**RDS 必带参数**。它基于 InnoDB 的可重复读（RR）隔离级别保证数据一致性，**避免了使用 `FLUSH TABLES WITH READ LOCK`**，从而不会因缺乏权限报错，也不会阻塞 RDS 的线上业务。
- `--regex '...'`：利用正则表达式过滤掉 `mysql`, `sys` 等系统库。RDS 的系统库通常有权限隔离，强行导出极易导致报错中断。
- `-c`：开启压缩，不仅节省磁盘空间，更重要的是能大幅降低网络带宽的瓶颈。

------

### 方案二：使用 `MySQL Shell` (mysqlsh) 方案（官方推荐、支持直传云存储）

MySQL Shell 包含的 Instance Dump Utility (`util.dumpInstance`) 是官方提供的新一代利器，速度通常比 `mydumper` 还要快，并且支持断点续传和直接将数据写到云对象存储（如 AWS S3, OCI Object Storage）。

#### 1. 前置准备与安装

- **安装**：从 MySQL 官方网站下载安装 `mysql-shell`。
- 版本建议使用 8.0.22 或更高版本，以获得最完善的并行与分块功能。

## 📄 开源数据库概述.md

数据库是支持一个或多个应用领域，按概念结构组织的数据集合， 其概念结构描述这些数据的特征及其对应实体间的联系。数据库中 的数据按一定的数据模型组织、描述和存储，具有较小冗余度、较高 数据独立性和易扩展性，并可为各种用户共享。数据库由于综合成 本低、处理能力高，扮演各类信息系统的核心角色。

从 20 世纪 60 年代至今，数据库的发展历程大致分为三个阶段，以通用电气集成数据存储(Integrated Data Store，IDS)网状层次数据库为代表的前关系阶段阶段，以Oracle、SQLSERVER、MySQL、Postgresql为代表的关系数据库阶段，以及以hadoop、Cassandra、Greenplum等为代表的后关系阶段。

在关系数据库阶段随着MySQL和Postgresql的广泛使用，开源数据库的市场份额增加。到今天，由于空间数据库、文档数据库、KV数据库、时序数据库 等非关系数据库的大量普及，开源数据库已成为数据引擎和数据管理的最流行的选项。
