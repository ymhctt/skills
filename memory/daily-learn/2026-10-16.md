## 一、问题概述

MySQL 主从环境下，为**无主键表**添加自增主键（AUTO_INCREMENT PRIMARY KEY）时，可能导致主从数据**永久性不一致**——且增删改查表面上都正常执行，极易被忽视。

**影响版本**：8.0.23、8.0.42、8.4.6 等多个版本均验证存在问题。

**相关Bug**：
- [Bug#103084](https://bugs.mysql.com/bug.php?id=103084)（本文案例来源）
- [Bug#92949](https://bugs.mysql.com/bug.php?id=92949)（并发更新场景下添加自增主键）
- [Bug#117241](https://bugs.mysql.com/bug.php?id=117241)（同一行数据主从不一致 + 后续复制链式影响）

**触发条件**（三者同时满足）：
1. 表**无主键**或非空唯一键（需要用 GEN_CLUST_INDEX + RowID 组织数据）
2. 存在**未提交事务**插入数据，另一个事务后提交
3. 在此基础上执行 `ALTER TABLE ... ADD AUTO_INCREMENT PRIMARY KEY`

## 📄 Redis Cluster（集群）进行数据槽位（Slot）迁移.md


这是一组非常硬核的底层命令！你贴出的这四行代码，完整地描绘了 **Redis Cluster（集群）进行数据槽位（Slot）迁移的底层运转机制**。

在日常运维中，我们通常会使用 `redis-cli --cluster reshard` 这种高级工具来自动化完成扩缩容。但这些工具的底层，其实就是靠不断地循环执行你写的这几条原始命令来实现的。

理解了这些，你就真正摸透了 Redis 集群在迁移数据时，是如何做到“不停机、不丢数据”的。下面为你逐一详细拆解：

### 第一步：设置目标节点的状态（准备接客）

代码段

```
CLUSTER SETSLOT 300 IMPORTING <source-node-id>
```

- **在哪里执行**：目标节点（即将接收数据的机器）。
    
- **命令含义**：告诉目标节点：“请注意，你要开始从 `<source-node-id>` 这个源节点那里，接收第 `300` 号槽位（Slot）的数据了。”
    
- **底层作用**：目标节点收到这个指令后，会把该槽位标记为 `IMPORTING`（导入中）状态。此时，如果客户端带着 `ASKING` 标识来找它要 300 号槽位里的某个 Key，它就会破例受理，而不是像往常一样拒绝并重定向。
    

### 第二步：设置源节点的状态（准备送客）

代码段

```
CLUSTER SETSLOT 300 MIGRATING <target-node-id>
```

- **在哪里执行**：源节点（即将迁出数据的机器）。
    
- **命令含义**：告诉源节点：“你要开始把第 `300` 号槽位的数据，搬家到 `<target-node-id>` 去了。”
    
- **底层作用**：源节点把槽位标记为 `MIGRATING`（迁出中）状态。
    
- **⚠️ 核心精髓（ASK 重定向机制）**：一旦源节点进入这个状态，当客户端来找源节点读写 300 号槽位的某个 Key 时，会发生以下两种情况：
    
    1. 如果这个 Key **还没被搬走**（还在源节点本地）：源节点直接处理请求。
        
    2. 如果这个 Key **已经被搬走了**（或者根本不存在）：源节点会给客户端返回一个特殊的错误 `ASK <target-ip>:<port>`。客户端收到后，会立刻去连接目标节点，先发一条 `ASKING` 命令打招呼，然后再重新发送实际的读写操作。这就保证了迁移期间业务的连续性。
        

_(注意：必须先执行第一步，再执行第二步。如果反过来，源节点让客户端去目标节点找，而目标节点还没准备好接收，就会报错。)_

## 什么是 K9s？

K9s 是一个 Kubernetes 的 **Terminal UI 工具**，本质上是 kubectl 的增强交互版，把集群的实时状态以终端界面的形式呈现。

简单理解：
- kubectl 的增强交互版
- 终端里的集群实时驾驶舱
- 运维现场的"热感雷达"

它不是 GUI，也不是 Web Dashboard，而是一种非常典型的 Linux 运维风格工具。

设计哲学（如果你用过 htop/btop/lazydocker/ncdu，会秒懂）：
> 把高频操作压缩成一个按键，把信息密度压缩成一屏。

---

## 安装方式

```bash
# macOS
brew install derailed/k9s/k9s

# Linux
curl -sSfL https://github.com/derailed/k9s/releases/latest/download/k9s_Linux_amd64.tar.gz | tar xz
sudo mv k9s /usr/local/bin/

# Windows
scoop install k9s
```

安装后只要 ~/.kube/config 正确，直接输入 `k9s` 就能连上当前集群。
