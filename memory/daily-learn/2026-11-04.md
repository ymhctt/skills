# redis acl 命令

在Redis6.0之前的版本中，登陆Redis Server只需要输入密码（前提配置了密码 requirepass ）即 可，不需要输入用户名，而且密码也是明文配置到配置文件中，安全性不高。并且应用连接也使用该    
密码，导致应用有所有权限处理数据，风险也极高。在Redis6.0有了ACL之后，终于解决了这些不安 全的因素，可以按照不同的需求设置相关的用户和权限。本文来介绍下Redis 6.0 ACL相关的配置和 使用。

# 说明

```
Redis ACL 是向后兼容的，即默认情况下用户为default，使用的是requirepass配置的密码。要是不使用 
ACL功能，对旧版客户端来说完全一样。Redis Auth可以有2种方式进行工作：  
1:旧版本的使用方式，默认用户。兼容旧版本Redis的支持  
AUTH <password>  
2:新方式，还需要验证用户名  
AUTH <username> <password>  
因为需要验证用户名了，所以客户端的认证方式也多了参数： 

  ‐‐user <username>  验证用户名  
  ‐‐pass <password>  验证密码,是参数‐a的别名;配合‐‐user使用  
  ‐‐askpass          强制用户输入带有STDIN掩码的密码  

```

# 命令详解

```
> ACL help  
 1) ACL <subcommand> arg arg ... arg. Subcommands are:  
 2) LOAD                             ‐‐ 从ACL文件中重新载入用户信息.  
 3) SAVE                             ‐‐ 保存当前的用户配置信息到ACL文件.   4) LIST                             ‐‐ 以配置文件格式显示用户详细信息.  
 4) USERS                            ‐‐ 列出所有注册的用户名.  
 5) SETUSER <username> [attribs ...] ‐‐ 创建或则修改一个用户.  
 6) GETUSER <username>               ‐‐ 得到一个用户的详细信息.  
 7) DELUSER <username> [...]         ‐‐ 删除列表中的用户.  
 8) CAT                              ‐‐ 列出可用的类别.  
9) CAT <category>                   ‐‐ 列出指定类别中的命令.  
10) GENPASS [<bits>]                 ‐‐ 生成一个安全的用户密码.  
11) WHOAMI                           ‐‐ 返回当前的连接用户.  
12) LOG [<count> | RESET]            ‐‐ 显示ACL日志条目.  

```

## 📄 mariadb 10.11 表结构变更.md


在 MariaDB 10.11 这种比较新的 LTS 版本中，原生的 Online DDL (`ALGORITHM=INPLACE, LOCK=NONE`) 已经非常强大。但在面对千万级以上大表、对主从延迟极度敏感，或者在 Galera Cluster 中为了避免触发 TOI（Total Order Isolation，全生命周期锁表）时，第三方在线表结构变更（OSC）工具依然是刚需。

目前业界主流且能够与 MariaDB 10.11.16 配合使用的第三方 OSC 工具主要有以下几款：

### 1. pt-online-schema-change (Percona Toolkit)

这是目前最成熟、在 MariaDB 体系中使用最广泛的行业标准工具。

- **工作原理：** 基于**触发器（Triggers）**。它会创建一个带有新结构的新表，在旧表上创建 `INSERT/UPDATE/DELETE` 触发器，然后将旧表数据分块拷贝到新表，最后进行重命名切换。
    
- **与 MariaDB 10.11 的契合度：** 极高。Percona Toolkit 持续更新，对 MariaDB 的兼容性非常好。
    
- **优势：**
    
    - **Galera 原生支持：** 它可以完美绕过 Galera 的 TOI 机制，将原本致命的全集群 DDL 锁，转化为普通的 DML 写入流分布到集群中。
        
    - **自动流控：** 提供 `--max-load` 和 `--critical-load` 参数，能实时监控节点状态和主从延迟，一旦负载过高会自动暂停拷贝。
        
- **劣势：** 触发器会带来额外的系统开销；如果表上原本就有复杂的触发器或外键，处理起来会非常棘手。
    

### 2. gh-ost (GitHub's Online Schema Transmogrifier)

GitHub 开源的工具，代表了 OSC 工具的新一代架构。

- **工作原理：** **无触发器（Triggerless）**。它伪装成一个 Slave 从库，直接读取 Binlog（或从 Galera 的节点读取）来捕获增量变更，同时在后台拷贝历史数据。
    
- **与 MariaDB 10.11 的契合度：** 需要谨慎。gh-ost 最初是为 MySQL 设计的。由于 MariaDB 后来在 GTID 的实现和 Binlog 格式上与 MySQL 分道扬镳，gh-ost 在处理 MariaDB 特定的 GTID 时可能会有兼容性问题。**通常在 MariaDB 中使用 gh-ost 需要降级为基于传统的 File/Position 模式来读取 Binlog**。
    
- **优势：** 完全剥离了触发器带来的性能损耗，对源库的侵入性极小；支持在执行过程中随时暂停、恢复甚至动态调整拷贝速度。
    
- **劣势：** 配置门槛较高，在 MariaDB 集群中需要更严格的测试验证。
    

### 3. 企业级 SQL 审核与 AIOps 执行平台 (Archery / Yearning)

如果您不仅需要底层工具，还在构建数据库运维的标准化生态，建议关注这类平台。

- **工作原理：** 它们本身不是底层的搬砖工具，而是封装了 `pt-osc` 或 `gh-ost` 的 Web 端中间件。
    
- **优势：** * 将高危的 DDL 变更转化为“工单申请 -> 自动语法/索引审核 -> 预估影响行数 -> 定时/异步执行”的闭环。
    
    - 提供了非常丰富的 API，极度适合与自动诊断探针、监控系统以及大模型 AIOps 链路进行集成，实现变更过程的可视化与自动化追踪。

**一、根据PID过滤进程所有信息**

```text
#! /bin/bash
# Function: 根据用户输入的PID，过滤出该PID所有的信息
read -p "请输入要查询的PID: " P
n=`ps -aux| awk '$2~/^'$P'$/{print $11}'|wc -l`
if [ $n -eq 0 ];then
 echo "该PID不存在！！"
 exit
fi
echo "--------------------------------"
echo "进程PID: $P"
echo "进程命令：`ps -aux| awk '$2~/^'$P'$/{print $11}'`"
echo "进程所属用户: `ps -aux| awk '$2~/^'$P'$/{print $1}'`"
echo "CPU占用率：`ps -aux| awk '$2~/^'$P'$/{print $3}'`%"
echo "内存占用率：`ps -aux| awk '$2~/^'$P'$/{print $4}'`%"
echo "进程开始运行的时刻：`ps -aux| awk '$2~/^'$P'$/{print $9}'`"
echo "进程运行的时间：`ps -aux| awk '$2~/^'$P'$/{print $10}'`"
echo "进程状态：`ps -aux| awk '$2~/^'$P'$/{print $8}'`"
echo "进程虚拟内存：`ps -aux| awk '$2~/^'$P'$/{print $5}'`"
echo "进程共享内存：`ps -aux| awk '$2~/^'$P'$/{print $6}'`"
echo "--------------------------------"
```

**二、根据进程名过滤进程信息**

会显示出该进程名包含的所有线程

```text
#! /bin/bash
# Function: 根据输入的程序的名字过滤出所对应的PID，并显示出详细信息，如果有几个PID，则全部显示
read -p "请输入要查询的进程名：" NAME
N=`ps -aux | grep $NAME | grep -v grep | wc -l` ##统计进程总数
if [ $N -le 0 ];then
  echo "该进程名没有运行！"
fi
