## 📄 TDSQL、OB、TiDB对比.md

- 强同步

  - TDSQL：改进MySQL原生半同步机制，binlog写入至少一台从库后主库提交事务并返回。如binlog同步所有从库延迟则主库写入阻塞；可以人工降级成异步模式恢复主库写入； 强同步能保证数据不丢，如果大事务导致从库SQL线程消费relaylog延迟，主从同步还是存在延迟可能；
  - TiDB：TiKV使用Raft算法确保数据一致，数据变更会落地成一条raft日志，复制并应用到多数派Region节点后写入成功；
  - OB：OB使用Paxos算法保障数据一致，数据通过Paxos协议进行日志同步，复制并应用到多数派分区后写入成功；

- 分片模式

  - TDSQL：分布式实例的分片表根据shardkey取模后存入对应的分片物理表中，如图所示；TDSQL支持Range和List二级

  ![image-20210305100733614](TDSQL、OB、TiDB对比.assets/image-20210305100733614.png)

  - TiDB：在TiKV中数据存放在有序的KV键值对中，整个 Key-Value 空间分成很多段也叫Region，每一段是一系列连续的 Key，默认96M；TiKV按Region组织存储，分散和复制；TiDB支持Range和Hash分区；

  ![image-20210305101110031](TDSQL、OB、TiDB对比.assets/image-20210305101110031.png)

  ![image-20210305101127083](TDSQL、OB、TiDB对比.assets/image-20210305101127083.png)

  

  - OB：OB按分区组织存储、分散和复制数据；OB的分区对应表的Hash、List和Range分区；每一个分区还支持二级分区；

  ![image-20210305102310795](TDSQL、OB、TiDB对比.assets/image-20210305102310795.png)

- 全局唯一索引

  - TDSQL：分片表shardkey必须是该表主键和所有唯一索引的一部分；
  - TDSQL：索引都是全局索引，也是KV键值对；主键和唯一索引的Value存储数据的RowID
  - OB：使用GLOBAL关键字创建全局索引

- 全局序列

  - TDSQL：

    ```
    　CREATE SEQUENCE 序列名
    　[INCREMENT BY n]
    　[START WITH n]
    　[{MAXVALUE/ MINVALUE n| NOMAXVALUE}]
    　[{CYCLE|NOCYCLE}]
    　[{CACHE n| NOCACHE}];
    ```

  - TiDB：

    ```text
    CREATE [TEMPORARY] SEQUENCE [IF NOT EXISTS] sequence_name
        [ INCREMENT [ BY | = ] increment ]
        [ MINVALUE [=] minvalue | NO MINVALUE | NOMINVALUE ]
        [ MAXVALUE [=] maxvalue | NO MAXVALUE | NOMAXVALUE ]
