这是一组非常硬核的底层命令！你贴出的这四行代码，完整地描绘了 **Redis Cluster（集群）进行数据槽位（Slot）迁移的底层运转机制**。

在日常运维中，我们通常会使用 `redis-cli --cluster reshard` 这种高级工具来自动化完成扩缩容。但这些工具的底层，其实就是靠不断地循环执行你写的这几条原始命令来实现的。

理解了这些，你就真正摸透了 Redis 集群在迁移数据时，是如何做到“不停机、不丢数据”的。下面为你逐一详细拆解：

### 第一步：设置目标节点的状态（准备接客）

代码段

```
CLUSTER SETSLOT 300 IMPORTING <source-node-id>
```

- **在哪里执行**：目标节点（即将接收数据的机器）。
    
- **命令含义**：告诉目标节点：“请注意，你要开始从 `<source-node-id>` 这个源节点那里，接收第 `300` 号槽位（Slot）的数据了。”
    
- **底层作用**：目标节点收到这个指令后，会把该槽位标记为 `IMPORTING`（导入中）状态。此时，如果客户端带着 `ASKING` 标识来找它要 300 号槽位里的某个 Key，它就会破例受理，而不是像往常一样拒绝并重定向。
    

### 第二步：设置源节点的状态（准备送客）

代码段

```
CLUSTER SETSLOT 300 MIGRATING <target-node-id>
```

- **在哪里执行**：源节点（即将迁出数据的机器）。
    
- **命令含义**：告诉源节点：“你要开始把第 `300` 号槽位的数据，搬家到 `<target-node-id>` 去了。”
    
- **底层作用**：源节点把槽位标记为 `MIGRATING`（迁出中）状态。
    
- **⚠️ 核心精髓（ASK 重定向机制）**：一旦源节点进入这个状态，当客户端来找源节点读写 300 号槽位的某个 Key 时，会发生以下两种情况：
    
    1. 如果这个 Key **还没被搬走**（还在源节点本地）：源节点直接处理请求。
        
    2. 如果这个 Key **已经被搬走了**（或者根本不存在）：源节点会给客户端返回一个特殊的错误 `ASK <target-ip>:<port>`。客户端收到后，会立刻去连接目标节点，先发一条 `ASKING` 命令打招呼，然后再重新发送实际的读写操作。这就保证了迁移期间业务的连续性。

# MariaDB strict_password_validation 主从复制中断 (MDEV-10956)

> **客户**：华泰证券股份有限公司
> **版本**：MariaDB 10.1.14
> **现象**：备库重放 `SET PASSWORD FOR xxx = '*hash*'` 时主从复制中断
> **Bug 链接**：https://jira.mariadb.org/browse/MDEV-10956
> **整理人**：婷婷
> **整理日期**：2026-06-15

---

## 一、问题现象

MariaDB 10.1.14 主备架构下，从库 SQL 线程停止：

```
Last_SQL_Error: Error 'The MariaDB server is running with the 
--strict-password-validation option so it cannot execute this statement' 
on query. Default database: 'xxl'. 
Query: 'SET PASSWORD FOR `psxxl`@`%` = '*522C9234B1E398D8E75031CACAB5D39C86860EE''
```

---

## 二、根因分析

**这是 MariaDB 官方已确认的 Bug（MDEV-10956）**。

### 触发链

1. **主库**：`SET PASSWORD FOR xxx = PASSWORD('xxx')` 执行成功
2. **binlog**：密码**不记明文**，只记录哈希值（`SET PASSWORD FOR xxx = '*hash*'`）
3. **从库**：SQL 线程回放时遇到 `SET PASSWORD` 哈希形式
4. **strict_password_validation=ON**（默认开启）拒绝该语句
5. **SQL 线程停止** → 复制中断

### 关键点

- 早期 MariaDB 版本（如 10.1.14）**没有排除复制线程**（applier thread）
- 即便密码本身合法，从库也会拒绝执行
- 报错是 ERROR 级别（不是 WARNING），SQL 线程直接停止

### 涉及参数

| 参数 | 默认值 | 行为 |
|------|--------|------|
| `strict_password_validation` | **ON** | ON 时所有改密码语句必须可校验；OFF 时哈希形式也接受 |
