## 核心理念

`free` 看 used 一片红不一定真有压力——Linux 会把空闲 RAM 全拿去做 **page cache**。**内存泄漏的定义不是"用得多"，而是"只增不减，从不释放"**。

排查不是盯 `used` 发呆，而是**层层下钻**：系统整体 → 内核细分 → 进程级别 → 内存段 → 时间趋势。

---

## 第一招：别看 used，看 available

```bash
$ free -m
              total        used        free      shared   buff/cache   available
Mem:          31941        8423         177        1092       23341       21966
```

- `used` 8423MB 看着吓人，但 `available` 还有 21966MB
- `buff/cache` 里那 23GB **随时可释放**给应用，所以这个值不低就没事
- **available** 是内核估算的「还能给新进程用多少」

> 💡 万一 `available` 确实只剩几百 MB——`free` 只告诉你"不够了"，不告诉你"谁吃的"，继续往下看。

### ⚠️ 扩展：容器时代看 `cgroup` 而非整机 `free`

Docker / K8s / Podman 场景下，整机 `free` 显示的 `available` **对容器不可见**——page cache 在 cgroup v1 时代全局共享，cgroup v2 才有 `memory.current` / `memory.high` / `memory.max`：

```bash
# 容器视角查看（推荐 cgroup v2）
cat /sys/fs/cgroup/system.slice/docker-<container_id>.scope/memory.current
cat /sys/fs/cgroup/system.slice/docker-<container_id>.scope/memory.max
cat /sys/fs/cgroup/system.slice/docker-<container_id>.scope/memory.events   # low/high/max/oom 计数
cat /sys/fs/cgroup/system.slice/docker-<container_id>.scope/memory.pressure  # PSI 压力指标

# 容器内进程视角
cat /sys/fs/cgroup/memory.current          # 当前使用
cat /sys/fs/cgroup/memory.swap.current      # 交换区使用
```

> 💡 cgroup v1 时容器内的 RSS 经常虚高（因为只看到 page cache，不算上），导致 OOM Kill 难以预测；cgroup v2 的 `memory.pressure` 提供 PSI（Pressure Stall Information）指标，可量化内存压力对吞吐的影响。

1.数据库大表信息查看

# 

统计某库下各表大小 不要存在过大的表信息。本身分配内存有限，过大的表会不停地刷新新旧数据，IO交付频繁，导致性能衰减。

```
SELECT TABLE_SCHEMA,
       TABLE_NAME TABLE_NAME, TABLE_ROWS,
                  CONCAT(ROUND(data_length / (1024 * 1024), 2),'M') data_length,
                  CONCAT(ROUND(index_length / (1024 * 1024), 2),'M') index_length,
                  CONCAT(ROUND(ROUND(data_length + index_length) / (1024 * 1024),2),'M') total_size,
                  engine
FROM INFORMATION_SCHEMA.TABLES
WHERE TABLE_SCHEMA NOT IN ('INFORMATION_SCHEMA' ,
                           'performance_schema',
                           'sys',
                           'mysql') 
ORDER BY (data_length + index_length) DESC LIMIT 10;
```
