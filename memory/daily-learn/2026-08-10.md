## 📄 MySQL认证插件变更文档 .md

从MySQL 8.0.3开始，引入了一个新的身份验证插件 caching_sha2_password,在MySQL 8.0.4中，caching_sha2_password是默认的身份验证插件。是sha256_password身份验证插件功能的超集,实现SHA-256身份验证，同时在服务器端使用缓存以获得更好的性能，并具有更广泛的适用性的附加功能。既解决安全性问题又解决性能问题，因此不推荐使用sha256_password。

使用使用caching_sha2_password进行身份验证的帐户的客户端必须使用安全连接(使用TCP使用TLS/SSL凭据、Unix套接字文件或共享内存进行连接)，或者使用RSA密钥对支持密码交换的未加密连接。同时服务器端插件使用sha2_cache_cleaner审计插件作为助手来执行密码缓存管理。sha2_cache_cleaner和caching_sha2_password一样，都是内置的，不需要安装。

MySQL支持设置用户的身份验证插件，可以使用如下SQL查询当前用户的插件

```
SELECT user, plugin FROM mysql.user;
```

如需将用户的身份验证插件从mysql_native_password修改为caching_sha2_password，需注意一下几点：

1、caching_sha2_password 需要客户端驱动支持（MySQL Connector/J 8.0+、Connector/Python 8.0+、PHP PDO 7.4+ 等）。

2、应用程序需显式启用 SSL 或支持 RSA 公钥交换，如JDBC url需添加参数`allowPublicKeyRetrieval=true&useSSL=false`

3、修改插件后，用户密码需重新生成。不能直接修改用户的插件设置

4、caching_sha2_password依赖 RSA 密钥对（默认自动生成）。



- 变更步骤：

1、确保所有客户端驱动版本支持 `caching_sha2_password`（如 Connector/J ≥ 8.0.11）。

2、检查当前用户插件设置，并记录

```
mysql> SELECT user,host, plugin FROM mysql.user;
+---------------+-----------+-----------------------+
| user          | host      | plugin                |
+---------------+-----------+-----------------------+
| root          | localhost | mysql_native_password |
| mysql.session | localhost | mysql_native_password |
| mysql.sys     | localhost | mysql_native_password |
| root          | %         | mysql_native_password |
+---------------+-----------+-----------------------+
4 rows in set (0.00 sec)
```

3、检查默认插件及服务端RSA配置

```
# 查看默认插件设置（只读），8.0.4以后应该默认为caching_sha2_password，如之前设置成mysql_native_password需修改my.cnf并重启
select @@global.default_authentication_plugin;

#服务器端 RSA 配置，均需要打开（1）
select @@global.sha256_password_auto_generate_rsa_keys;
select @@global.caching_sha2_password_auto_generate_rsa_keys;

### 1、编译安装MySQL

1、MySQL源码下载,建议下载自带boost的版本

`https://cdn.mysql.com//Downloads/MySQL-8.0/mysql-boost-8.0.26.tar.gz`

2、安装cmak，建议用brew安装

```
brew install cmake
brew install gcc
brew install openmpi

```

3、编译安装MySQL

```

mysqld_safe --defaults-file=/Users/yangminghan/Documents/mysql/my.cnf &

## 📄 Redis不同数据结构的常用命令.md

直观参考，按数据结构排列：

---

## String（字符串）

最基础的类型，存二进制安全的字节序列，最大 512MB。

| 命令 | 作用 |
|:---|:---|
| `SET key val [EX s] [NX]` | 设值，可带过期秒数 / 仅 key 不存在时写入 |
| `GET key` | 取值 |
| `MGET k1 k2 ...` | 批量取值 |
| `INCR` / `INCRBY` / `DECR` | 原子增减（计数器） |
| `SETNX key val` | 不存在才设值（分布式锁） |
| `GETSET key val` | 设新值返回旧值 |
| `APPEND key val` | 尾部追加 |

**场景**：缓存、计数器、分布式锁、Session 共享。

---

## Hash（哈希）

字段-值的映射表，适合存对象。

| 命令 | 作用 |
|:---|:---|
| `HSET key f v [f v ...]` | 设字段值 |
| `HGET key f` | 取字段值 |
| `HMGET key f1 f2` | 批量取 |
| `HGETALL key` | 取全部字段（小心大 Key） |
| `HINCRBY key f n` | 字段原子增减 |
| `HEXISTS key f` | 判断字段是否存在 |
| `HDEL key f` | 删除字段 |
| `HLEN key` | 字段数量 |

**场景**：用户信息、购物车、对象缓存（比 String 存 JSON 更灵活：可单独更新字段）。

---

## List（列表）

双向链表，有序可重复，头尾操作 O(1)。

| 命令 | 作用 |
|:---|:---|
| `LPUSH` / `RPUSH key v` | 左/右插入 |
| `LPOP` / `RPOP key` | 左/右弹出 |
| `BLPOP key timeout` | 阻塞弹出（消息队列） |
