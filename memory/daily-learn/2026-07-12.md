## 📄 MySQL processlist中command和STATE各值的含义.md

之前在处理一个客户故障的时候，被问到Creating sort index、Update、Sending data、statistics等状态值的含义，官方文档里的描述太过模糊，例如文档中解释 state状态为query的含义是“The thread is getting ready to start updating the table.” 线程正在准备去更新一张表，WTF？准备工作有哪些，能不能详细点??? 趁有空，试着整理下以备查用。

在information_schema和performance_schema中都有processlist，从8.0.20开始支持使用参数performance_schema_show_processlist 指定show processlist的数据来源，为了避免mutex，获得更好的性能建议使用performance_schema。

show Processlist 默认返回以下8列信息

| 字段名  | 含义                                                         |
| ------- | ------------------------------------------------------------ |
| Id      | 连接标识。等于processlist表的ID列和 pfs.threads表的PROCESSLIST_ID |
| User    | 发起连接和操作的MySQL用户名，此外system user是内部线程（host空）如备库上的io、sql线程。event_scheduler是用来监控计划任务的线程。unauthenticated user表示已连接但还未对用户进行身份验证的线程。 |
| Host    | 连接的客户端信息，TCP连接以host_name:client_port的形式返回   |
| db      | 连接的数据库，如未use则为空                                  |
| Command | 连接正在执行的命令类型，该类型可对应到Com_xxx的status状态值。常见的是sleep和query |
| Time    | 连接处于当前状态持续的时间，单位为秒。对于备库的SQL线程，该值等于执行的最后一个event的时间戳与备库当前时间的差值。 |
| State   | 线程正在执行的操作、事件或状态。**通常持续的时间很短，如果持续几秒就需要调查原因。** |
| Info    | 线程正在执行的语句，如果没有执行语句，则为NULL。该语句可能是发送到服务器的语句，或者如果语句执行其他语句，则可能是最内部的语句。例如，如果CALL语句执行正在执行SELECT语句的存储过程，Info值将显示SELECT语句。 |



## Command

- Binlog Dump

这是主备复制的主上的线程，用于将二进制日志内容发送到备库。

- Change user

线程正在执行更改用户操作。

- Close stmt

线程正在关闭一个prepared statement。

- Connect

由备库的复制线程和work线程使用。

- Connect Out

备库正在连接到主库。

- Create DB

线程正在创建数据库。

- Daemon

标识该线程是服务器的内部线程。

- Debug
