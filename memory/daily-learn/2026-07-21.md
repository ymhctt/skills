### 1、编译安装MySQL

1、MySQL源码下载,建议下载自带boost的版本

`https://cdn.mysql.com//Downloads/MySQL-8.0/mysql-boost-8.0.26.tar.gz`

2、安装cmak，建议用brew安装

```
brew install cmake
brew install gcc
brew install openmpi
brew install fltk
brew install fftw
```

3、编译安装MySQL

```
cd 
cmake . -DCMAKE_INSTALL_PREFIX=/Users/yangminghan/Documents/mysql -DMYSQL_DATADIR=/Users/yangminghan/Documents/mysql/data -DWITH_DEBUG=1  -DSYSCONFDIR=/usr/local/  -DMYSQL_TCP_PORT=3306  -DWITH_BOOST=/Users/yangminghan/Documents/mysql-8.0.26/boost    -DFORCE_INSOURCE_BUILD=1

make && make install

export PATH=$PATH:/Users/yangminghan/Documents/mysql/bin

#将之前安装的mysql删除
brew list
brew uninstall mysql

#编辑配置文件
/Users/yangminghan/Documents/mysql/my.cnf
#初始化
mysqld --defaults-file=/Users/yangminghan/Documents/mysql/my.cnf --user=yangminghan --initialize
#启动服务
mysqld_safe --defaults-file=/Users/yangminghan/Documents/mysql/my.cnf &
#创建用户修改密码
alter user 'root'@'localhost' identified by 'Tcdn@2007';
create user 'root'@'%' identified by 'Tcdn@2007';
grant all privileges on *.* to 'root'@'%' with grant option;
```

## 📄 POC要求和流程.md

POC（Proof of Concept，概念验证）是在大规模部署、全面采购或正式立项之前，为了验证某个概念、技术方案或产品是否可行、能否解决特定业务痛点而进行的小规模实验。

通俗地说，**POC 不是为了做一个完美的产品，而是为了“排雷”和“证明价值”。**

## POC的定义与核心要求

一个合格的 POC 必须具备极强的目的性和边界感。如果失控，POC 很容易变成一个无休止的免费试用期。核心要求包括：

- **目标明确（Clear Objectives）：** 必须清楚要证明什么行，或者什么不行（例如：验证架构能否支撑百万并发，或者新系统能否将审批时间缩短一半）。
    
- **边界清晰（Bounded Scope）：** 严格限定测试的范围、功能模块和参与人员，防范“范围蔓延”（Scope Creep）。
    
- **周期短且固定（Time-boxed）：** 通常在 2 周到 2 个月之间。到期必须出结论，切忌无限期拖延。
    
- **环境真实（Realistic Context）：** 必须使用脱敏后的真实业务数据和尽量贴近生产的测试环境，理想状态下的“跑分”没有意义。
    

## 衡量POC成功的核心指标 (Success Criteria)

在启动 POC 之前，双方（业务方与技术提供方）必须对以下指标达成共识，并建立量化的评分卡（Scorecard）：

|**指标维度**|**评估重点**|**成功标准示例**|
|---|---|---|
|**功能覆盖率**|核心业务流程是否能顺利跑通，痛点是否被解决。|“必须满足的”核心功能通过率大于 90%。|
|**性能与稳定性**|在真实负载和极限情况下的表现。|接口响应时间小于 200 毫秒，支持 1000 并发。|
|**集成与兼容性**|与企业现有系统（如 ERP、CRM、SSO）的对接成本。|API 接口完全兼容，单点登录接入工期小于 3 天。|
|**易用性**|终端用户的学习成本、界面逻辑和操作体验。|关键任务的操作步数较原系统减少 30%。|
|**安全性**|数据安全、合规性、权限控制体系。|支持企业级 RBAC 权限体系，敏感字段可加密存储。|
|**商业 ROI**|预估的商业价值与整体实施成本。|预计节约人力成本 20%，整体系统拥有成本符合预算。|

## 完备的POC执行流程 (SOP)

如果步骤错乱，比如还没定好评估标准就开始搭建环境，POC 极易走向失败。以下是一个可直接执行的完整流程：

**1.需求对齐与立项：**决定 POC 生死的关键一步。

- **挖掘痛点：** 收集业务部门的真实诉求，确定本次 POC 要解决的 1 到 3 个核心问题。
    
- **定义验收标准：** 将上述“核心指标”具体化，形成表格，明确什么是“通过”，什么是“不通过”。
    
- **分配资源：** 确定参与团队（项目经理、业务体验官、IT 运维、安全审核员）及时间投入。
    

**2.方案设计与环境搭建：**确保测试环境尽量贴近真实生产。

- **制定排期：** 明确每个里程碑（Kick-off、中期检查、最终评审）的日期。
    
- **输出测试用例：** 编写具体的测试场景和步骤（例如：“销售人员在断网环境下提交订单，恢复网络后的同步情况”）。
    
- **数据与环境准备：** 准备脱敏的真实业务数据，完成软硬件或云资源的开通与初始化配置。
