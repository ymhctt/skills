## 📄 brm恢复MogDB实例pg_probackup.conf丢失怎么办.md

brm恢复备份数据时，在备份目录中存在pg_probackup.conf。如果该文件丢失，恢复会报错

![image-20240102144806004](/Users/yangminghan/Library/Application Support/typora-user-images/image-20240102144806004.png)

从报错信息可知 system identifier 不一致，导致恢复报错。

pg_probackup.conf中记录了备份实例的相关信息，其中最重要的有以下两点

```
PGDATA — the path to the data directory of the cluster to back up.

system-identifier — the unique identifier of the PostgreSQL instance.

```

所以，只要找到备份文件的system identifier，构造一个正确的system identifier就可以实施恢复操作了。可以使用pg_controldata来获取，具体的方法如下：

```
使用 pg_controldata 读取 备份的控制文件相关信息
[omm@mogdb1 database]$ pg_controldata  /home/omm/dbback/backups/test/S6E157/database |grep "Database system identifier"
Database system identifier:           22613235661898231
```

## 📄 MogDB常用查询SQL.md



### 通过系统线程id查对应的query

```
#!/bin/bash source ~/.bashrc thread_sets=`ps -ef |grep -i gaussdb |grep -v grep|awk -F ' ' '{print $2}'|xargs top -n 1 -bHp |grep -i ' worker'|awk -F ' ' '{print $1}'|tr "\n" ","|sed -e 's/,$/\n/'` gsql -p 26000 postgres -c "select  pid,lwtid,state,query from pg_stat_activity a,dbe_perf.thread_wait_status s where a.pid=s.tid and lwtid in($thread_sets);" 
```

### 查看hang住SQL的堆栈信息

```
--查sql对应的线程id（lwtid） select pid,lwtid,state,query from pg_stat_activity a,dbe_perf.thread_wait_status s where a.pid=s.tid and query like '%xxx%'; --查线程的堆栈信息 pstack lwtid 
```

### 查看当前数据库下所有表的注释信息

```
\dt+ 或 select current_database(),nspname as schema ,relname,description from pg_class c ,pg_namespace n,pg_description d where c.relnamespace=n.oid  and c.oid=d.objoid  and d.objsubid=0  and nspname not in('pg_catalog','db4ai'); 
```

### 查看当前数据库下所有表字段的注释信息

```
\d+ 或 select current_database(),nspname as schema ,relname,attname as column ,atttypid::regtype as datatype,objsubid,atthasdef as default,description from pg_class c ,pg_namespace n,pg_attribute a,pg_description d where c.relnamespace=n.oid  and a.attrelid=c.oid  and c.oid=d.objoid  and a.attnum>0  and d.objsubid=0  and nspname not in('pg_catalog','db4ai'); 
```

### 查看主备角色

```
select pg_is_in_recovery();
#主库返回f ； 备库返回 t
```





### 查看复制槽

```
select slot_name,coalesce(plugin,'_') as plugin,slot_type,datoid,coalesce(database,'_') as database,       (case active when 't' then 1 else 0 end)as active,coalesce(xmin,'_') as xmin,dummy_standby,       pg_xlog_location_diff(CASE WHEN pg_is_in_recovery() THEN restart_lsn ELSE pg_current_xlog_location() END , restart_lsn)  AS delay_lsn from pg_replication_slots; 
```

### 查看主备延迟

```
--主库 select client_addr,sync_state,pg_xlog_location_diff(pg_current_xlog_location(),receiver_replay_location) from pg_stat_replication; 
--备库 select now() AS now,        coalesce(pg_last_xact_replay_timestamp(), now()) replay,       extract(EPOCH FROM (now() - coalesce(pg_last_xact_replay_timestamp(), now()))) AS diff; 
```
