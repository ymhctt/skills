## 📄 linux cache缓存清理.md

drop_caches的值可以是0-3之间的数字，代表不同的含义
0：不释放（系统默认值
1：释放页缓存
2：释放dentries和inodes
3：释放所有缓存
执行如下命令释放所有缓存

```bash
sync    ##执行释放缓存先使用sync同步一下，防止引起数据错误
echo 3 > /proc/sys/vm/drop_caches
```

## 📄 MogDB中max_dynamic_memory的大小.md

我们在使用和运维MogDB的时候可能会遇到内存不足导致的问题，报错信息通常为“memory is temporarily unavailable”或者“memory usage reach the max_dynamic_memory。”

通过查询gs_total_memory_detail视图可以得到实例当前内存使用情况，如下

其中max_process_memory是该实例能够使用的最大内存，属于POSTMASTER类型参数，重启才能生效。最佳实践要求该服务器上所有实例的max_process_memory之和不能超过物理内存的80%。

视图和报错中的max_dynamic_memory是指最大动态内存，我们可以通过dynamic_peak_memory值了解到动态内存使用的历史峰值。那么现在问题来了，max_dynamic_memory的值是由哪些参数来控制的呢？是否可以动态调整？

在src/common/backend/utils/mmgr/memprot.cpp文件中定义了max_dynamic_memory(maxChunksPerProcess)

```
maxChunksPerProcess = ((unsigned int)avail_mem >> BITS_IN_KB) - reserved_mem;
```

其中avail_mem的定义如下，既增加max_process_memory 或 减少 cstore_buffers 和 udf_memory_limit 的设置可以增加max_dynamic_memory。

```
int avail_mem = g_instance.attr.attr_memory.max_process_memory - g_instance.attr.attr_storage.cstore_buffers - udf_memory - (size >> BITS_IN_KB);
```
