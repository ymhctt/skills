## 📄 FIO性能指标测试.md

测试用例

```
磁盘的 IOPS 可以通过 fio 这个工具来测试，下面的语句是我用来测试磁盘随机读写的命令 
fio -filename=$filename -direct=1 -iodepth 1 -thread -rw=randrw -ioengine=psync -bs=16k -size=500M -numjobs=10 -runtime=10 -group_reporting -name=mytest 
```





一、fio参数介绍

fio总共有100+个参数，很多参数我们用不到，下面选择性能测试中一些常用的参数进行说明。

首先来看一条fio命令：

fio -name=fiotest.qcow2 -filename=test.qcow2  -group_reporting  -iodepth=16 -ioengine=gfapi_async -volume=vol_rep2 -brick=127.0.0.1 -nrfiles=1 -rw=randwrite -bs=4k -size=1G -threads -numjobs=1 -direct=1

该命令式在挂载点下随机写一个1G的文件，测试挂载点的性能，具体参数的意义如下：

-name: 用于输出信息用的名字，在上述命令行的使用方法中，表明一个新job的开始，缺省为job name

-filename： 测试文件名称，通常选择需要测试的盘的data目录

-group_reporting：汇总所有的信息，而不是每个job都显示具体的结果

-iodepth：本次测试的队列深度

-ioengine：负载产生的引擎，定义job向文件发起io的方式。Fio的引擎有很多，具体可以网上搜一下，常用的引擎为libaio 和 gfapi_async，测试过程中，如果要模拟api的方式测试挂载点的性能则用gfapi_async，测试裸盘或其他块设备性能时，选用libaio即可。

-volume 和 -brick：这两个是测试挂载点用的，其他场景不需要。

-nrfiles：每个进程生成的文件数量

-rw： 读写方式，顺序读，顺序写，随机读，随机写，混合读写

-bs： 块大小，一般测试4k, 8k, 64k, 128k, 1M

-size： 测试文件的大小

-threads：fio默认会使用fork()创建job，如果这个选项设置的话，fio将使用pthread_create来创建线程

-numjobs：创建的线程数量

-direct： 测试过程绕过机器自带的buffer，相当于o_direct

其他一些相对高级点用法的参数，比如：

-runtime：测试时长

## 📄 opengauss命令行工具使用.md

- gsql连接参数

```
-d 选项: 指定 gsql 客户端连接的数据库
-h 选项: 指定 gsql 客户端连接的服务器 IP
-U 选项: 指定 gsql 客户端连接数据库的用户名 
-p 选项: 指定 gsql 客户端连接的服务器端口号 
-W 选项: 指定 gsql 客户端连接的用户密码
*-r 选项：use libedit， 设置后 在命令行中方面的进行删除、粘贴、上翻等操作
*-E 让 gsql 客户端程序执行元命令的时候，显示其对应的 SQL 语句
-t 让 gsql 客户端程序在执行 SQL 查询语句的时候，返回的结果不显示列名及返 回结果的行数。
-A 让 gsql 客户端程序在执行 SQL 查询语句的时候，不对齐显示查询返回的行数 一般和-t同时使用 -At
-v 让 gsql 客户端程序在命令行中设置 gsql 环境变量； eg gsql -d studentdb -h 192.168.100.91 -U student -p 26000 -W student@ustb2020 -v -r
*-c 让 gsql 客户端程序直接在命令行中运行 SQL 语句 ； eg gsql -d studentdb -h 192.168.100.91 -U student -p 26000 -W student@ustb2020  -c "select * from instructor where salary=80000"
*-f 让 gsql 客户端程序直接在命令行中直接运行 SQL 脚本文件 gsql -d studentdb -h 192.168.100.91 -U student -p 26000 -W student@ustb2020 -f test.sql

```

## 📄 MySQL processlist中command和STATE各值的含义.md

之前在处理一个客户故障的时候，被问到Creating sort index、Update、Sending data、statistics等状态值的含义，官方文档里的描述太过模糊，例如文档中解释 state状态为query的含义是“The thread is getting ready to start updating the table.” 线程正在准备去更新一张表，WTF？准备工作有哪些，能不能详细点??? 趁有空，试着整理下以备查用。

在information_schema和performance_schema中都有processlist，从8.0.20开始支持使用参数performance_schema_show_processlist 指定show processlist的数据来源，为了避免mutex，获得更好的性能建议使用performance_schema。

show Processlist 默认返回以下8列信息

| 字段名  | 含义                                                         |
| ------- | ------------------------------------------------------------ |
| Id      | 连接标识。等于processlist表的ID列和 pfs.threads表的PROCESSLIST_ID |
| User    | 发起连接和操作的MySQL用户名，此外system user是内部线程（host空）如备库上的io、sql线程。event_scheduler是用来监控计划任务的线程。unauthenticated user表示已连接但还未对用户进行身份验证的线程。 |
| Host    | 连接的客户端信息，TCP连接以host_name:client_port的形式返回   |
| db      | 连接的数据库，如未use则为空                                  |
| Command | 连接正在执行的命令类型，该类型可对应到Com_xxx的status状态值。常见的是sleep和query |
| Time    | 连接处于当前状态持续的时间，单位为秒。对于备库的SQL线程，该值等于执行的最后一个event的时间戳与备库当前时间的差值。 |
| State   | 线程正在执行的操作、事件或状态。**通常持续的时间很短，如果持续几秒就需要调查原因。** |
| Info    | 线程正在执行的语句，如果没有执行语句，则为NULL。该语句可能是发送到服务器的语句，或者如果语句执行其他语句，则可能是最内部的语句。例如，如果CALL语句执行正在执行SELECT语句的存储过程，Info值将显示SELECT语句。 |



## Command

- Binlog Dump

这是主备复制的主上的线程，用于将二进制日志内容发送到备库。

- Change user

线程正在执行更改用户操作。

- Close stmt

线程正在关闭一个prepared statement。

- Connect

由备库的复制线程和work线程使用。

- Connect Out

备库正在连接到主库。

- Create DB

线程正在创建数据库。

- Daemon

标识该线程是服务器的内部线程。

- Debug
