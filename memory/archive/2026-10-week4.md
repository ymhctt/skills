### 3️⃣ 🔧 真·故障 Q 修复 —— `.gitmodules` 缺失导致早间汇总 cron 间歇性崩溃 ⚡⚡⚡⚡⚡

**现象**：10/28 07:20 `9fc7ca81`（早间汇总）`status=error` / `delivered=0`
- summary = `⚠️ 🛠️ Exec failed: print text → run git rev-list → ... → run git submodule (agent)`
- 10/27 ok/del=1，10/23-10/25 全 error → **间歇复发**

**根因（真因，非表象）**：
- 仓库有**两个已跟踪 gitlink（mode 160000）**：`document`（`84b3761`）+ `skills/obsidian-skills`（`fa1e131`）
- 但根目录**没有 `.gitmodules` 文件** → `git submodule status` fatal：
  `no submodule mapping found in .gitmodules for path 'document'` → 汇总 cron 走到该步就崩，整条推送链断
- **为何 git_sync 7:00 一直 ok**：`scripts/pull-document.sh` = `cd document && git pull origin main` → **直接进子目录，绕开 submodule 映射检查**；只有汇总 cron 会调 `git submodule` → 这就是间歇性根源

**修复**（内部配置修复，静默期合法 = AGENTS.md 规则四）：
1. 备份 `.git/config` → 新建 `.gitmodules`（两个 path/url/branch 按实际 remote 抄）
2. `git submodule init` ×2 → commit `bd7f887` → `git push workspace master:openclaw-workspace`

**验证 6 项全过**：`git submodule status` 两行 SHA + exit 0 / 无 fatal / 两子仓 SHA = gitlink 记录值 / dirty 0,0 / `pull-document.sh` `Already up to date.` / 上下游 `0 0`

**预防**：新增 gitlink 后**必须**确认 `.gitmodules` 已入库；`git ls-files -s | awk '$1=="160000"'` 可列出全部 gitlink 对照 `.gitmodules` 条目数。

**教训**：故障 Q 历史那些「间歇 Exec failed」若每次都复现命令看真实 stderr，**10/23 就能修好** —— 不要满足于「工具层问题，等自愈」。
