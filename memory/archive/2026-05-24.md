## 一、行级锁

InnoDB 支持行级别粒度的并发控制，主要有以下几种锁类型：

### 1.1 LOCK_REC_NOT_GAP

锁只加在记录本身，不锁记录之前的 GAP。在 **RC 隔离级别**下，一般加的都是该类型的记录锁。

例外：唯一二级索引上的 duplicate key 检查，总是加 `LOCK_ORDINARY` 类型的锁。

### 1.2 LOCK_GAP

只锁一段范围，不锁记录本身。通常表示两个索引记录之间、索引第一条记录之前、或最后一条记录之后的锁。

一般在 **RR 隔离级别**下会使用 GAP 锁。

> 可通过切换到 RC 隔离级别，或开启 `innodb_locks_unsafe_for_binlog` 来避免 GAP 锁。

### 1.3 LOCK_ORDINARY（Next-Key Lock）

包含记录本身及记录之前的 GAP。用于解决 RR 隔离级别下的**幻读问题**。

**示例：** 索引上有记录 1, 4, 5, 8, 12，执行 `SELECT...WHERE col > 10 FOR UPDATE` 时，如果在 (8, 12) 之间不加 Gap 锁，另一个 Session 插入记录 9 后再执行相同查询，就会看到新插入的记录（幻读）。

### 1.4 LOCK_S（共享锁）

用于事务中读取行记录，不希望被其他事务修改。

**请求 S 锁的场景：**

| 场景 | 锁类型 |
|------|--------|
| SERIALIZABLE 隔离级别下的普通查询 | LOCK_S |
| SELECT ... IN SHARE MODE | RC: `LOCK_REC_NOT_GAP \| LOCK_S`<br>RR 非唯一等值: `LOCK_ORDINARY \| LOCK_S` |
| INSERT 发现 duplicate key | 普通 INSERT/UPDATE: `LOCK_S`<br>REPLACE/INSERT ON DUPLICATE: `LOCK_X` |
| 外键检查 | `LOCK_S` |
| INSERT ... SELECT | 对 SELECT 的表加 `LOCK_S` |

### 1.5 LOCK_X（排他锁）

避免对同一条记录的并发修改。UPDATE、DELETE、SELECT ... FOR UPDATE 都会加排他锁。
