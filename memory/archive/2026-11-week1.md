| 11-07 | 08:00 error → 08:03 ok | 07:20 ok |
| 11-08 | 08:00 error → 08:04 ok | 07:20 ok |

**规律**：error 一律是 `cron: job execution timed out (last phase: model-call-started)`，**卡点固定在 08:00 整点后 180 秒**（= 07:20 同理）。每个 error 后 2~4 分钟内同 job 自动重跑 ok 并成功投递。
→ **判据固化**：`cron_run_receipts` 中 error 后面紧跟同 job 的 ok，即为 fallback/重试自愈，**不需告警、不需补跑**（补跑会造成重复推送）。
→ **根因判断**：MiniMax-M3 在 07:20~08:00 早高峰窗口模型 idle timeout，属日内峰值瓶颈（与已归档的故障 M「日内峰值」定性一致，非月度耗尽）。
