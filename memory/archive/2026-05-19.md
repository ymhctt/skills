## 📄 Troubleshooting InnoDB Data Dictionary Operations.md

Information about table definitions is stored both in the `.frm` files, and in the InnoDB [data dictionary](https://dev.mysql.com/doc/refman/5.7/en/glossary.html#glos_data_dictionary). If you move `.frm` files around, or if the server crashes in the middle of a data dictionary operation, these sources of information can become inconsistent.

If a data dictionary corruption or consistency issue prevents you from starting `InnoDB`, see [Section 14.22.2, “Forcing InnoDB Recovery”](https://dev.mysql.com/doc/refman/5.7/en/forcing-innodb-recovery.html) for information about manual recovery.

#### CREATE TABLE Failure Due to Orphan Table



A symptom of an out-of-sync data dictionary is that a [`CREATE TABLE`](https://dev.mysql.com/doc/refman/5.7/en/create-table.html) statement fails. If this occurs, look in the server's error log. If the log says that the table already exists inside the `InnoDB` internal data dictionary, you have an orphan table inside the `InnoDB` tablespace files that has no corresponding `.frm` file. The error message looks like this:

```terminal
InnoDB: Error: table test/parent already exists in InnoDB internal
InnoDB: data dictionary. Have you deleted the .frm file
InnoDB: and not used DROP TABLE? Have you used DROP DATABASE
InnoDB: for InnoDB tables in MySQL version <= 3.23.43?
InnoDB: See the Restrictions section of the InnoDB manual.
InnoDB: You can drop the orphaned table inside InnoDB by
InnoDB: creating an InnoDB table with the same name in another
InnoDB: database and moving the .frm file to the current database.
InnoDB: Then MySQL thinks the table exists, and DROP TABLE will
InnoDB: succeed.
```

You can drop the orphan table by following the instructions given in the error message. If you are still unable to use [`DROP TABLE`](https://dev.mysql.com/doc/refman/5.7/en/drop-table.html) successfully, the problem may be due to name completion in the [**mysql**](https://dev.mysql.com/doc/refman/5.7/en/mysql.html) client. To work around this problem, start the [**mysql**](https://dev.mysql.com/doc/refman/5.7/en/mysql.html) client with the [`--skip-auto-rehash`](https://dev.mysql.com/doc/refman/5.7/en/mysql-command-options.html#option_mysql_auto-rehash) option and try [`DROP TABLE`](https://dev.mysql.com/doc/refman/5.7/en/drop-table.html) again. (With name completion on, [**mysql**](https://dev.mysql.com/doc/refman/5.7/en/mysql.html) tries to construct a list of table names, which fails when a problem such as just described exists.)

#### Cannot Open Datafile



With [`innodb_file_per_table`](https://dev.mysql.com/doc/refman/5.7/en/innodb-parameters.html#sysvar_innodb_file_per_table) enabled (the default), the following messages may appear at startup if a [file-per-table](https://dev.mysql.com/doc/refman/5.7/en/glossary.html#glos_file_per_table) tablespace file (`.ibd` file) is missing:

```terminal
[ERROR] InnoDB: Operating system error number 2 in a file operation.
[ERROR] InnoDB: The error means the system cannot find the path specified.
[ERROR] InnoDB: Cannot open datafile for read-only: './test/t1.ibd' OS error: 71
[Warning] InnoDB: Ignoring tablespace `test/t1` because it could not be opened.
```

To address these messages, issue [`DROP TABLE`](https://dev.mysql.com/doc/refman/5.7/en/drop-table.html) statement to remove data about the missing table from the data dictionary.

#### Cannot Open File Error



Another symptom of an out-of-sync data dictionary is that MySQL prints an error that it cannot open an `InnoDB` file:

```terminal
ERROR 1016: Can't open file: 'child2.ibd'. (errno: 1)
```
