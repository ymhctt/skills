# MySQL SQL 回溯 - 手工查询手册

> 本手册从 `mysql_sql_retrospect.py` 中整理出全部 SQL，用于**不方便运行脚本的场景**（堡垒机只能贴 SQL、无 Python 环境、给同事直接查等）。
>
> - 前置条件：`performance_schema=ON`，语句事件消费者已开启（见第七章先自查）
> - 所需权限：`SELECT ON performance_schema.*`（查询）；`UPDATE ON performance_schema.*`（改配置，第八章）
> - **时间单位**：performance_schema 的 `*_TIMER_*` / `*_TIME` / `CPU_TIME` 列均为**皮秒**（1e-12 秒）。换算：`/1000000000000`=秒、`/1000000000`=毫秒、`/1000000`=微秒。手册中的 SQL 已尽量带上换算表达式

---

## 一、连接与版本确认

### 1.1 确认连接与版本
```sql
-- 用途: 确认连到的实例和版本（决定 CPU/内存指标是否可用：8.0.28+ 才有 CPU_TIME，8.0.31+ 才有 MAX_TOTAL_MEMORY）
SELECT VERSION();
```

### 1.2 能力探测（判断版本支持哪些指标列）
```sql
-- 用途: 探测 summary 表是否有 CPU/内存/95分位 列（SUM_CPU_TIME、MAX_TOTAL_MEMORY 需 8.0.28/8.0.31+）
-- 返回 1=支持，0=不支持（老版本查询中直接引用该列会报错，先探测）
SELECT COUNT(*) FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA='performance_schema'
  AND TABLE_NAME='events_statements_summary_by_digest'
  AND COLUMN_NAME='SUM_CPU_TIME';      -- 逐个替换列名: MAX_TOTAL_MEMORY / QUANTILE_95

SELECT COUNT(*) FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA='performance_schema'
  AND TABLE_NAME='events_statements_history_long'
  AND COLUMN_NAME='CPU_TIME';          -- 或 MAX_TOTAL_MEMORY
```

## 二、SQL 时段回溯 - summary 模式（digest 汇总）

> 数据源 `events_statements_summary_by_digest`：按"语句指纹"聚合的累计指标。时间窗语义：`LAST_SEEN >= 开始时间 AND FIRST_SEEN <= 结束时间`（窗口内**执行过**即可，指标是自统计以来的**累计值**，非时段增量）。

### 2.1 通用模板（总耗时降序 TOP 20）
```sql
-- 用途: 查指定时间段内执行过的 SQL 汇总，按总耗时降序。
--      替换 @start/@end 为实际时间，如 '2026-08-30 09:00:00'
SELECT
    SCHEMA_NAME        AS db,
    DIGEST_TEXT        AS sql_digest,                                        -- 语句摘要，? 是参数占位符
    COUNT_STAR         AS exec_count,                                       -- 执行次数
    ROUND(SUM_TIMER_WAIT/1e12, 2)  AS total_sec,                            -- 总耗时(秒)
    ROUND(AVG_TIMER_WAIT/1e9,  2)  AS avg_ms,                               -- 平均耗时(毫秒)
    ROUND(MAX_TIMER_WAIT/1e9,  2)  AS max_ms,                               -- 最大耗时(毫秒)
    ROUND(SUM_LOCK_TIME/1e9,  2)  AS lock_ms,                               -- 总锁等待(毫秒)
    SUM_ROWS_EXAMINED  AS rows_examined,                                    -- 累计扫描行
    SUM_ROWS_SENT      AS rows_sent,                                        -- 累计返回行
    SUM_CREATED_TMP_TABLES      AS tmp_tables,                              -- 内存临时表次数
    SUM_CREATED_TMP_DISK_TABLES AS tmp_disk_tables,                         -- 磁盘临时表次数（临时文件）
    SUM_SORT_MERGE_PASSES       AS sort_merge_passes,                       -- filesort 落盘合并趟数（临时文件）
    SUM_SELECT_SCAN    AS full_scan,                                        -- select 全表扫描次数
    SUM_SELECT_FULL_JOIN AS full_join,                                      -- join 全表扫描次数
    SUM_NO_INDEX_USED  AS no_index,                                         -- 未走索引次数
    ROUND(100.0*SUM_NO_INDEX_USED/COUNT_STAR, 0) AS no_index_pct,           -- 无索引比例%
    FIRST_SEEN, LAST_SEEN
FROM performance_schema.events_statements_summary_by_digest
WHERE DIGEST IS NOT NULL
  AND LAST_SEEN  >= '2026-08-30 09:00:00'   -- @start: 窗口开始
  AND FIRST_SEEN <= '2026-08-30 12:00:00'   -- @end:   窗口结束
  -- AND SCHEMA_NAME = 'your_db'            -- 可选: 只看某个库
  -- AND DIGEST_TEXT LIKE '%orders%'        -- 可选: 按语句内容模糊过滤
ORDER BY SUM_TIMER_WAIT DESC                -- 排序键见 2.2
LIMIT 20;
```

### 2.2 排序键速查（替换 ORDER BY 列）
| 排序目标 | ORDER BY 列 | 说明 |
|---|---|---|
| 执行次数 | `COUNT_STAR` | 最频繁 |
| 总耗时 | `SUM_TIMER_WAIT` | 累计贡献最大 |
| 平均耗时 | `AVG_TIMER_WAIT` | 单次最慢 |
| 最大耗时 | `MAX_TIMER_WAIT` | 尾延迟 |
| 锁时间 | `SUM_LOCK_TIME` | 锁热点 |
| 扫描行 | `SUM_ROWS_EXAMINED` | IO 放大 |
| 返回行 | `SUM_ROWS_SENT` | |
| 临时表 | `SUM_CREATED_TMP_TABLES` | |
| 磁盘临时表/临时文件 | `SUM_CREATED_TMP_DISK_TABLES` | 落盘 |
| 排序落盘 | `SUM_SORT_MERGE_PASSES` | filesort 合并趟数 |
| 全表扫描 | `SUM_SELECT_SCAN` | |
| join 全表扫 | `SUM_SELECT_FULL_JOIN` | |
| 无索引次数 | `SUM_NO_INDEX_USED` | |
| **CPU** | `SUM_CPU_TIME` | **8.0.28+ 且需 events_statements_cpu 消费者开启** |
| **内存峰值** | `MAX_TOTAL_MEMORY` | **8.0.31+** |
| 95分位耗时 | `QUANTILE_95` | 8.0.28+ |

### 2.3 8.0.28+ 完整版（含 CPU/内存/95分位）
```sql
-- 用途: 新版本(8.0.28+)额外带上 CPU 总耗时、内存峰值、95分位耗时
SELECT
    SCHEMA_NAME AS db,
    LEFT(DIGEST_TEXT, 60) AS sql_digest,
    COUNT_STAR AS exec_count,
    ROUND(SUM_TIMER_WAIT/1e12, 2) AS total_sec,
    ROUND(SUM_CPU_TIME/1e12, 2)   AS cpu_sec,      -- CPU 总耗时(秒)，需 events_statements_cpu 消费者
    ROUND(MAX_TOTAL_MEMORY/1e6, 1) AS max_mem_mb,  -- 单语句内存峰值(MB)，8.0.31+
    ROUND(QUANTILE_95/1e9, 2)    AS p95_ms,        -- 95分位耗时(毫秒)
    SUM_CREATED_TMP_DISK_TABLES AS tmp_disk,
    SUM_SORT_MERGE_PASSES AS sort_merge,
    SUM_SELECT_SCAN AS full_scan,
    LAST_SEEN
FROM performance_schema.events_statements_summary_by_digest
WHERE DIGEST IS NOT NULL
  AND LAST_SEEN >= '2026-08-30 09:00:00'
  AND FIRST_SEEN <= '2026-08-30 12:00:00'
ORDER BY SUM_CPU_TIME DESC           -- 按 CPU 排；可换 MAX_TOTAL_MEMORY / QUANTILE_95
LIMIT 20;
```

> 注意：`SUM_CPU_TIME`/`CPU_TIME` 全为 0 时，先检查 `events_statements_cpu` 消费者（第七章 7.2 / 第八章），这是**默认关闭**的。

## 三、SQL 时段回溯 - history 模式（真实 SQL 文本）

> 数据源 `events_statements_history_long`：环形缓冲，默认只保留**最近约 1 万条**事件，但保存**真实完整 SQL 文本**，可直接拿去 EXPLAIN。适合"刚出问题"看现场。

### 3.1 计算事件发生时间（前置）
```sql
-- 用途: 换算近似墙钟时间。事件的 TIMER_START 是自服务器启动的皮秒数，
--      事件时间 ≈ (NOW - Uptime) + TIMER_START/1e12 秒。
--      在 SQL 里可用下面方式直接得到启动时刻:
SELECT NOW(6) AS now_ts,
       VARIABLE_VALUE AS uptime_s,
       TIMESTAMPADD(SECOND, -VARIABLE_VALUE, NOW(6)) AS boot_time   -- 服务器启动时刻
FROM performance_schema.global_status
WHERE VARIABLE_NAME='Uptime';
```

### 3.2 查询最近执行的真实 SQL（按耗时降序）
```sql
-- 用途: 查 history_long 中最近执行的语句事件，含真实 SQL 文本、耗时、扫描行、临时表等
--      事件时间为启动时刻+TIMER_START 换算的近似墙钟时间
SELECT
    -- 近似事件时间 = 服务器启动时刻 + TIMER_START(皮秒)/1e12 秒（秒级精度，已够定位问题时段）
    TIMESTAMPADD(SECOND, TRUNCATE(TIMER_START/1000000000000, 0),
        (SELECT TIMESTAMPADD(SECOND, -VARIABLE_VALUE, NOW(6))
         FROM performance_schema.global_status WHERE VARIABLE_NAME='Uptime')
    ) AS approx_event_time,
    CURRENT_SCHEMA AS db,
    ROUND(TIMER_WAIT/1e12, 4) AS exec_sec,             -- 执行耗时(秒)
    ROUND(LOCK_TIME/1e9, 2)   AS lock_ms,              -- 锁等待(毫秒)
    ROWS_SENT, ROWS_EXAMINED, ROWS_AFFECTED,
    CREATED_TMP_TABLES, CREATED_TMP_DISK_TABLES,
    ERRORS, MYSQL_ERRNO,
    SQL_TEXT                                            -- 真实 SQL（受 max_sql_text_length 截断，默认1024字节）
FROM performance_schema.events_statements_history_long
WHERE SQL_TEXT IS NOT NULL
  AND DIGEST IS NOT NULL
  AND EVENT_NAME LIKE 'statement/sql/%'    -- 只要客户端提交的 SQL 事件（排除存储过程内部等）
  -- AND CURRENT_SCHEMA = 'your_db'
  -- AND SQL_TEXT LIKE '%orders%'
ORDER BY TIMER_WAIT DESC                   -- 可换: TIMER_START(时间序) / ROWS_EXAMINED / CPU_TIME 等
LIMIT 50;
```

> 简化版（不换算时间，适合快速看）：把 `approx_event_time` 一列删掉即可。
> 8.0.28+ 可加 `ROUND(CPU_TIME/1e12,3) AS cpu_sec`；8.0.31+ 可加 `MAX_TOTAL_MEMORY`。

## 四、IO 视图

### 4.1 表级 IO（含 InnoDB 缓冲池命中）
```sql
-- 用途: 按表统计读写计数与耗时，找 IO 热点表。注意含缓冲池命中（逻辑 IO），读多不代表物理 IO
SELECT
    OBJECT_SCHEMA AS db, OBJECT_NAME AS tbl,
    COUNT_STAR    AS total_io,
    ROUND(SUM_TIMER_WAIT/1e12, 2) AS total_sec,
    COUNT_READ, COUNT_WRITE,
    COUNT_FETCH, COUNT_INSERT, COUNT_UPDATE, COUNT_DELETE,
    ROUND(SUM_TIMER_FETCH/1e12, 2) AS fetch_sec
FROM performance_schema.table_io_waits_summary_by_table
WHERE OBJECT_SCHEMA NOT IN ('mysql','performance_schema','sys')  -- 排除系统库
  AND COUNT_STAR > 0
ORDER BY COUNT_STAR DESC          -- 可换 SUM_TIMER_WAIT / COUNT_READ / COUNT_WRITE
LIMIT 20;
```

### 4.2 文件级 IO（接近真实物理 IO）
```sql
-- 用途: 按文件类事件统计读写字节量，可观察 redo/binlog/data 文件的写放大
SELECT
    EVENT_NAME,                                    -- 如 wait/io/file/innodb/innodb_log_file
    COUNT_READ, COUNT_WRITE,
    SUM_NUMBER_OF_BYTES_READ  AS bytes_read,       -- 可套 ROUND(x/1024/1024,1) 变 MB
    SUM_NUMBER_OF_BYTES_WRITE AS bytes_written,
    ROUND(SUM_TIMER_READ/1e12, 2)  AS read_sec,
    ROUND(SUM_TIMER_WRITE/1e12, 2) AS write_sec
FROM performance_schema.file_summary_by_event_name
WHERE EVENT_NAME LIKE 'wait/io/file/%'
  AND (COUNT_READ + COUNT_WRITE) > 0
ORDER BY (SUM_NUMBER_OF_BYTES_READ + SUM_NUMBER_OF_BYTES_WRITE) DESC
LIMIT 20;
```

> 说明：MySQL 暂不支持 SQL 级 IO 归因，只有表级/文件级。

## 五、内存视图

### 5.1 线程级（每连接当前/峰值内存）
```sql
-- 用途: 找占内存最多的连接。需 thread_instrumentation 消费器 + memory 仪器开启
SELECT
    t.PROCESSLIST_ID AS conn_id,
    IFNULL(t.PROCESSLIST_USER,'-') AS user,
    IFNULL(t.PROCESSLIST_HOST,'-') AS host,
    IFNULL(t.PROCESSLIST_DB,'-')   AS db,
    SUM(m.CURRENT_NUMBER_OF_BYTES_USED) AS cur_bytes,   -- 可套 /1024/1024 变 MB
    SUM(m.HIGH_NUMBER_OF_BYTES_USED)   AS peak_bytes,
    COUNT(*) AS mem_events
FROM performance_schema.memory_summary_by_thread_by_event_name m
JOIN performance_schema.threads t USING(THREAD_ID)
WHERE t.PROCESSLIST_ID IS NOT NULL          -- 只看活跃连接（排除后台线程）
GROUP BY t.PROCESSLIST_ID, t.PROCESSLIST_USER, t.PROCESSLIST_HOST, t.PROCESSLIST_DB
ORDER BY SUM(m.CURRENT_NUMBER_OF_BYTES_USED) DESC
LIMIT 20;
```

### 5.2 全局内存（按分配器事件归因）
```sql
-- 用途: 看 InnoDB 缓冲池、各种 cache/heap 的当前与峰值占用
SELECT
    EVENT_NAME,                              -- 如 memory/innodb/buf_buf_pool
    CURRENT_COUNT_USED,
    CURRENT_NUMBER_OF_BYTES_USED,            -- 当前字节，可套 /1024/1024 变 MB
    HIGH_NUMBER_OF_BYTES_USED                -- 峰值字节
FROM performance_schema.memory_summary_global_by_event_name
WHERE CURRENT_NUMBER_OF_BYTES_USED > 0
ORDER BY CURRENT_NUMBER_OF_BYTES_USED DESC
LIMIT 20;
```

## 七、performance_schema 配置体检（只读查询）

### 7.1 基础开关
```sql
-- 用途: 总开关是否开启（OFF 时一切采集不可用，需 my.cnf 加 performance_schema=ON 后重启）
SELECT VARIABLE_VALUE FROM performance_schema.global_variables
WHERE VARIABLE_NAME='performance_schema';

-- 用途: sys 库是否存在
SELECT COUNT(*) FROM information_schema.SCHEMATA WHERE SCHEMA_NAME='sys';

-- 用途: THREAD_CPU 计时器是否可用（CPU_TIME 采集基础，8.0.28+ 且需 OS 支持）
SELECT TIMER_NAME, TIMER_FREQUENCY FROM performance_schema.performance_timers
WHERE TIMER_NAME='THREAD_CPU';
```

### 7.2 消费者状态（最常用！）
```sql
-- 用途: 查看全部消费者开关。重点看:
--   statements_digest(=digest汇总)、events_statements_history_long(=真实SQL回溯)
--   events_statements_cpu(=CPU指标，默认NO!)、events_waits_*(=锁/IO等待)
SELECT NAME, ENABLED FROM performance_schema.setup_consumers;
```

### 7.3 仪器启用情况
```sql
-- 用途: 逐族检查仪器启用/计时数量（替换 LIKE 模式: 'statement/%' / 'wait/io/%' /
--      'wait/lock/%' / 'stage/%' / 'transaction/%' / 'memory/%'）
SELECT COUNT(*) AS total,
       SUM(ENABLED='YES') AS enabled,
       SUM(TIMED='YES')   AS timed
FROM performance_schema.setup_instruments
WHERE NAME LIKE 'statement/%';

-- 用途: 单看某个仪器
SELECT NAME, ENABLED, TIMED FROM performance_schema.setup_instruments
WHERE NAME = 'statement/sql/select';
```

### 7.4 容量/大小参数（需重启才能改）
```sql
-- 用途: 查容量参数。默认值偏小会导致: SQL文本被截断(1024字节)、digest统计溢出丢弃、
--      history_long 缓冲易被冲走。调大需写 my.cnf 并重启（人工在维护窗口执行，不要自动做）
SELECT VARIABLE_NAME, VARIABLE_VALUE
FROM performance_schema.global_variables
WHERE VARIABLE_NAME IN (
  'performance_schema',
  'performance_schema_events_statements_history_long_size',  -- 默认10000，回溯大窗口可调大
  'performance_schema_events_statements_history_size',       -- 每线程10条
  'performance_schema_max_sql_text_length',                  -- 默认1024，建议4096，否则截断SQL
  'performance_schema_max_digest_length',                    -- 默认1024，建议2048-4096
  'performance_schema_digests_size',                         -- 默认10000，溢出丢统计
  'performance_schema_max_memory_instruments'                -- -1=自动；0=内存仪器全禁用
);
```

## 八、配置修改（动态，需 root/UPDATE 权限）

> ⚠️ **安全边界**：以下 UPDATE 仅内存生效、不重启、不影响业务，重启后自动恢复默认。**修改前先手工留存当前配置**（8.1 快照查询，把结果另存为文件）。**禁止执行 RESTART / SHUTDOWN / SET GLOBAL——这些只能由 DBA 在维护窗口人工择机执行。**

### 8.1 修改前留快照（手工版）
```sql
-- 用途: 修改前留存当前配置（相当于脚本的自动快照）。三段结果分别保存到文件备查
SELECT NAME, ENABLED FROM performance_schema.setup_consumers;
SELECT NAME, ENABLED, TIMED FROM performance_schema.setup_instruments;
SELECT VARIABLE_NAME, VARIABLE_VALUE FROM performance_schema.global_variables
WHERE VARIABLE_NAME IN ('performance_schema',
  'performance_schema_events_statements_history_long_size',
  'performance_schema_events_statements_history_size',
  'performance_schema_max_sql_text_length',
  'performance_schema_max_digest_length',
  'performance_schema_digests_size',
  'performance_schema_max_memory_instruments');
```

### 8.2 开启语句采集（basic 级，最常用）
```sql
-- 用途: 开启语句事件+digest+CPU 消费者（CPU 指标默认关闭，这就是 --sort cpu 拿不到数据的主因）
UPDATE performance_schema.setup_consumers SET ENABLED='YES'
WHERE NAME IN ('global_instrumentation','thread_instrumentation','statements_digest',
               'events_statements_current','events_statements_history',
               'events_statements_history_long','events_statements_cpu')
  AND ENABLED='NO';

-- 用途: 启用并计时全部语句仪器
UPDATE performance_schema.setup_instruments SET ENABLED='YES' WHERE NAME LIKE 'statement/%' AND ENABLED='NO';
UPDATE performance_schema.setup_instruments SET TIMED='YES'   WHERE NAME LIKE 'statement/%' AND TIMED='NO';
```

### 8.3 追加等待事件（waits 级：锁等待/IO 等待）
```sql
-- 用途: 开启等待事件消费者 + IO/锁仪器（配合 sys.innodb_lock_waits 分析锁等待）
UPDATE performance_schema.setup_consumers SET ENABLED='YES'
WHERE NAME IN ('events_waits_current','events_waits_history','events_waits_history_long')
  AND ENABLED='NO';

UPDATE performance_schema.setup_instruments SET ENABLED='YES' WHERE NAME LIKE 'wait/io/%'   AND ENABLED='NO';
UPDATE performance_schema.setup_instruments SET TIMED='YES'   WHERE NAME LIKE 'wait/io/%'   AND TIMED='NO';
UPDATE performance_schema.setup_instruments SET ENABLED='YES' WHERE NAME LIKE 'wait/lock/%' AND ENABLED='NO';
UPDATE performance_schema.setup_instruments SET TIMED='YES'   WHERE NAME LIKE 'wait/lock/%' AND TIMED='NO';
```

### 8.4 追加阶段/事务/内存（all 级）
```sql
-- 用途: 开启语句阶段(Sending data/Sorting等)、事务、内存采集
UPDATE performance_schema.setup_consumers SET ENABLED='YES'
WHERE NAME IN ('events_stages_current','events_stages_history','events_stages_history_long',
               'events_transactions_current','events_transactions_history','events_transactions_history_long')
  AND ENABLED='NO';

UPDATE performance_schema.setup_instruments SET ENABLED='YES' WHERE NAME LIKE 'stage/%'        AND ENABLED='NO';
UPDATE performance_schema.setup_instruments SET TIMED='YES'   WHERE NAME LIKE 'stage/%'        AND TIMED='NO';
UPDATE performance_schema.setup_instruments SET ENABLED='YES' WHERE NAME LIKE 'transaction/%'  AND ENABLED='NO';
UPDATE performance_schema.setup_instruments SET TIMED='YES'   WHERE NAME LIKE 'transaction/%'  AND TIMED='NO';
UPDATE performance_schema.setup_instruments SET ENABLED='YES' WHERE NAME LIKE 'memory/%'       AND ENABLED='NO';
```

### 8.5 回滚（按 8.1 留存的快照手工恢复）
```sql
-- 用途: 把消费者恢复为快照记录的值（把 <名字>/<YES|NO> 替换为快照内容，逐条执行；
--      带 ENABLED<>'X' 条件可保证重复执行幂等安全）
UPDATE performance_schema.setup_consumers SET ENABLED='NO'
WHERE NAME='events_statements_cpu' AND ENABLED<>'NO';

-- 仪器同理，可按批恢复:
UPDATE performance_schema.setup_instruments
SET ENABLED='NO', TIMED='NO'
WHERE NAME IN ('statement/sql/select','statement/sql/insert')
  AND (ENABLED<>'NO' OR TIMED<>'NO');

-- 恢复后复核:
SELECT NAME, ENABLED FROM performance_schema.setup_consumers;
```

### 8.6 清零重新统计（可选，按需）
```sql
-- 用途: 清空 digest 汇总，让统计从当前时刻重新累计（此后 summary 模式查到的就是"清零后"的增量）
--      ⚠️ 影响所有基于该表的既有统计（sys.statement_analysis 等），确认后再执行
TRUNCATE TABLE performance_schema.events_statements_summary_by_digest;
```

## 九、执行计划与开销（拿到 SQL 后）

> summary 模式的 `DIGEST_TEXT` 中 `?` 是参数占位符，**不能直接执行**，需替换为真实值（排查时可先替换为 NULL 尝试）。history 模式的 `SQL_TEXT` 可直接用。

```sql
-- 用途: 传统表格执行计划（全版本）
EXPLAIN SELECT * FROM orders WHERE user_id = 42;

-- 用途: JSON 格式，含优化器计算的总开销 query_cost 与各表 read_cost（伪成本，可相对比较；
--      手工看时在输出的 JSON 里搜 "query_cost" 和 "read_cost"）
EXPLAIN FORMAT=JSON SELECT * FROM orders WHERE user_id = 42;

-- 用途: 树形计划，8.0.16+
EXPLAIN FORMAT=TREE SELECT * FROM orders WHERE user_id = 42;

-- 用途: 真实执行并统计各算子实际行数/耗时，8.0.18+。
--      ⚠️ 会真实执行该 SQL（DML 也会被执行），生产环境务必确认后再用！
EXPLAIN ANALYZE SELECT * FROM orders WHERE user_id = 42;

-- 用途: 先临时改优化器开关再出计划，对比开关对计划/开销的影响（同一会话内先 SET 再 EXPLAIN）
SET SESSION optimizer_switch='mrr=off';
EXPLAIN FORMAT=JSON SELECT * FROM orders WHERE user_id = 42;
```

## 十、典型手工排查流程（5 步）

```sql
-- ① 体检: 消费器都开了吗？（重点: statements_digest / events_statements_history_long / events_statements_cpu）
SELECT NAME, ENABLED FROM performance_schema.setup_consumers;

-- ② 若没开 → 先按 8.1 留快照，再执行 8.2 开启语句采集（等 5-10 分钟积累数据）

-- ③ 回溯: summary 模式找时段内耗时 TOP SQL（2.1 模板，替换时间窗与排序键）

-- ④ 取真实 SQL: history 模式看最近执行原文（3.2，刚出问题时用）

-- ⑤ 分析: 把拿到的 SQL 套第九章 EXPLAIN FORMAT=JSON 看 query_cost；
--        需要对比优化器行为时先 SET SESSION optimizer_switch 再 EXPLAIN
```

## 附：常见"查不到数据"排查对照

| 现象 | 原因 | 处理 |
|---|---|---|
| summary 表全空 | statements_digest 消费者未开启 | 8.2 开启 |
| CPU 列全为 0 | events_statements_cpu 未开启（默认关） | 8.2 开启 |
| history 查不到 | history_long 消费者未开启 / 缓冲被冲走 | 8.2 开启；调大容量参数（7.4，需重启） |
| SQL 文本尾部截断 | max_sql_text_length 默认 1024 字节 | 调大（需重启） |
| digest 数量比实际少 | digests_size 溢出丢弃 | 调大（需重启） |
| memory 视图全空 | memory 仪器未开启 | 8.4 开启 |
| CPU_TIME 列不存在 | 版本 < 8.0.28 | 升级，或用耗时近似 |
| 时间不准（history） | 近似墙钟时间（启动时刻+TIMER_START 换算） | 属正常，误差在秒级 |
